## 서비스 흐름과 개발 범위

**기업 검색·업종 선택 → 자료 수집·기준 통일 → 재무·주석 분석 → 규칙 위험 패널·12개월 위험 사건 예측(검증 충족 시 확률, 미충족 시 표시 보류) → 담당자 체크·검토 기록 → 담당자의 최종 판단**

핵심 개발 범위는 영업이익·현금흐름·차입/상환·운전자본 시각화, 실적 변동 분석, 공통/업종 주석 추출·요약, 6개 판단 축과 경고/주의/관찰을 표시하는 N-S04 위험 패널, 재무·주석 결합 12개월 위험 사건 예측, 확인 체크와 검토 기록 초안입니다. 예측 확률은 검증 조건을 충족한 모델에 한해 제공하며, 미학습·검증 중·검증 미충족 시 확률을 표시하지 않고 상태와 보류 사유를 제공합니다. 뉴스는 보완 기능이며 초기 예측 모델 입력에서 제외합니다.

숫자·비율은 분석 코드로 계산하고, AI는 주석 구조화와 근거 있는 요약에 활용합니다. 예측 모델은 재무 단독 기준 모델과 비교 검증하며, 최종 여신 판단은 담당자가 수행합니다. 상세 기획은 [프로젝트 문서](https://github.com/loansight-ai/docs/blob/main/README.md)에서 관리합니다.

## 최신 범위와 검증 기준

- 대상은 제조·건설·도소매·부동산 임대 4개이며 장비/물품 렌탈·운수/창고·금융/보험·지주/스팩·부동산 관리/중개는 제외합니다.
- 공통 주석 6항목과 업종별 사전, 원문 구간/교차참조, 제공/수취·현재/전기·한도/잔액과 검출/공시상 없음/미검출/추출 실패를 구분합니다. 미검출·금액 미기재를 0/없음으로 바꾸지 않습니다.
- 규칙 단계·미래 모델 확률·담당자 체크는 별도로 관리합니다. 단계 수치는 팀 가설이며 현직자 확인·모델 수용/보류·최소 비교 표본은 미정입니다.
- 위험 사건의 후보 범위는 원리금 연체·기한이익상실·지급거절·회생/채권은행 관리절차 신청·감사의견 변형/계속기업 불확실성입니다. 상환과 무관한 관리종목·상장폐지는 제외합니다. 후보 사건은 공시 원문과 대조하며, 공시에서 확인된 사건을 실제 은행 대출 연체와 동일시하지 않습니다. 유형별 심각도, 복합 라벨 구성, 사건 인정·발생일 판정, 중복 사건 처리, 12개월 추적 미완료 표본 처리, 모델 수용·보정 기준은 미정입니다.
- 공시 시점 입력·향후 12개월 추적·기업/시간 분리와 누출을 검증하고, 같은 평가 표본으로 재무 기준/결합 모델과 확률 보정을 비교합니다.
- 기능 검증 15곳·정답지 5곳은 논의 필요이며 모델·추출·계정 확보 표본과 구분합니다. 실제 성과를 미리 확정하지 않습니다.
- [최신 문서·원문](https://app.notion.com/p/40080be201ba8159ae7fcd1aebce0000) · [WBS v1.1·69개 작업](https://app.notion.com/p/3ff80be201ba80618c52cb61cc4a6153). 요구 43개·기능 41개·화면 8개·미정 질문 20개를 기준으로 구현과 검수를 연결합니다.

## 기술 구성과 배포

| 영역 | 설계 방향 |
|---|---|
| 프론트엔드 | React + Vite + TypeScript, TanStack Query. React Router·Tailwind CSS는 잠정 |
| API·분석 | FastAPI와 별도 Python Worker, 동일 코드베이스 사용 |
| 데이터 | PostgreSQL 잠정 채택, 원문은 로컬 볼륨/PVC와 Storage Adapter로 보관 |
| 작업 전달 | RabbitMQ, Transactional Outbox, publisher confirm·수동 ACK·멱등 처리 |
| 진행 알림 | SSE로 GNB·상세 화면 갱신, 서버 상태·이벤트로 새로고침·재방문 복구 |
| AI 연동 | LLM 공급자와 ML 추론을 Port & Adapter로 분리 |
| 배포 | SaaS 우선·k3s 지향, Docker Compose 기반 Self-hosted 지원 |

Frontend와 Backend 두 개의 애플리케이션 이미지를 사용합니다. API·Worker·Outbox Relay는 같은 Backend 이미지의 실행 명령만 구분하고, PostgreSQL·RabbitMQ는 별도 인프라로 운영합니다. 브라우저는 동일 출처의 `/api`로 접근합니다. 상태 변경 내부 알림은 PostgreSQL `LISTEN/NOTIFY`를 잠정 사용하고 영속 이벤트를 재생합니다.

GNB는 사용자별 진행 중 작업과 미확인 완료·실패 알림을 표시합니다. 로그인·Workspace 식별 방식은 미정이지만, 사용자별 GNB·SSE 또는 다중 사용자 검토 기능 공개 전에는 서버 측 식별·접근 범위를 확정합니다. PWA·OS 푸시 알림은 초기 범위에서 제외합니다.

## 목표 디렉터리 구조

다음은 설계 문서에 따른 **구현 목표 구조**이며, 아직 생성된 실행 코드나 배포 파일을 뜻하지 않습니다. 상세 모듈 구성은 아키텍처 문서 3절을 따릅니다.

```text
code/
├── frontend/             # React SPA, GNB·SSE 상태 관리
├── backend/              # FastAPI·Worker·Outbox Relay, migrations·tests
├── ml-training/          # 선택: 데이터셋·학습·평가
├── deploy/
│   ├── compose.yaml      # Self-hosted / 로컬 운영
│   └── k8s/              # k3s 기본 구성·SaaS overlay
├── scripts/              # 설치·업그레이드·백업·복구
├── docs/                 # 코드에 종속된 산식·규칙·데이터·API 계약
├── .env.example
├── LoanSight_AI_Architecture_v0.3.md
└── README.md
```

## 실행 환경 및 실행 방법

아키텍처 v0.3에 따라 React SPA·FastAPI·Python Worker·PostgreSQL·RabbitMQ 골격부터 구현합니다. 이후 실제 기업 보고서 한 건을 수집→정규화→재무지표→주석 근거→규칙 판정→화면 조회까지 연결하고, AI·ML을 단계적으로 확장합니다.
이 저장소에서 재현 가능한 실행 환경·버전·의존성·실행 명령은 코드 반영 후 확정합니다.
실행 가능한 코드가 추가되면 의존성 파일과 처음부터 끝까지 실행하는 방법을 이 문서에 기록합니다.
현재는 실행할 프로그램이 없으며 실행 검증을 수행하지 않았습니다.
