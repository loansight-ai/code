# LoanSight AI 프론트엔드

React + Vite + TypeScript로 구현한 첫 번째 화면 골격입니다. 백엔드 없이 **가상 기업과 공통 예시 수치**로 실행하며, 실제 분석 결과를 제공하지 않습니다.

## 실행

Node.js **24.22.1**과 pnpm **10.34.9**를 사용합니다. 의존성은 `package.json`과 `pnpm-lock.yaml`에 고정했습니다.

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

개발 주소는 `http://127.0.0.1:5173`입니다. PowerShell 실행 정책으로 `pnpm.ps1`이 차단되는 환경에서는 `pnpm.cmd`로 실행합니다.

```sh
pnpm build
pnpm preview
pnpm lint
pnpm format:check
pnpm test
pnpm test:e2e
```

브라우저 테스트는 설치된 Google Chrome을 사용합니다. Chrome이 없다면 설치하거나 `playwright.config.ts`의 브라우저 설정을 개발 환경에 맞게 변경합니다. 빌드 산출물은 `dist/`이며, 운영 서버에서는 SPA 경로를 `index.html`로 fallback해야 합니다. 운영 배포 설정은 이번 범위에 포함하지 않았습니다.

## 구현 범위

| 화면                | 현재 동작                                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 기업 검색           | 가상 기업 7개, 검색·업종 필터, 대상/복합/미분류/제외 상태와 판정 사유, 보고서·연결/별도 선택                              |
| 직접 입력·업종 변경 | 출처·기준일·변경 사유·근거를 검증하는 초안 폼, 예시 원본과 입력값 비교, 브라우저 저장·복원·이력                           |
| 공통 셸             | KB 색상 토큰, 반응형 메뉴, 선택 전 분석 메뉴 비활성, 출처/예시 표시, 작업 안내 Dialog, 공통 로딩/자료 없음/실패/보류 표시 |
| 재무 요약·실적 변동 | ECharts 추세와 정렬 가능한 TanStack Table, 재무 화면 지연 로딩                                                            |
| 주석·위험징후       | 가상 원문 Dialog, 예시 원문 확인 전 체크 비활성                                                                           |
| 위험 예측           | 외부 모델·입력 계약·검증 결과 미연동에 따른 보류 표시, 확률 미표시                                                        |
| 담당자 검토         | 기업·보고서·회계 범위별 브라우저 메모 저장·복원, 예시/분석 기준을 포함한 복사                                             |

검색 조건은 URL의 `q`·`industry`, 기업 선택 화면의 분석 기준은 `company`·`report`·`scope`, 분석 화면은 `/analyses/{demo-id}/{section}?report={year}&scope={CFS|OFS}`로 유지합니다. 분석 화면에서 기업 검색으로 돌아가거나 새로고침해도 선택한 기준을 복원합니다. 필터에서 선택 기업이 숨겨져도 우측에 선택과 해제 안내를 유지합니다. 잘못된 기업·보고서·회계 범위가 URL에 있으면 분석 진입을 막고 기준 초기화를 제공합니다.

예시 7개는 대상 4개, 복합·미분류·제외 각 1개입니다. 제외 기업은 선택 불가이며, 복합·미분류 예시는 실제 업종 근거와 서버의 업종 변경·재분석이 미연동이므로 분석 진입을 보류합니다. 이는 미정인 복합 업종 비중·변경 권한을 확정한 운영 정책이 아닙니다. 미분류에 임의 업종을 배정하거나 제외 예시에 직접 URL로 분석 진입할 수 없습니다.

연도 선택지는 레이아웃 확인을 위한 예시이며 실제 제공 기간을 확정한 정책이 아닙니다. 모든 기업·보고서·회계 범위에서 같은 2023~2025 재무 예시를 사용하므로 선택 조건별 실제 결과로 해석하지 않습니다.

브라우저 메모는 `loansight.demo.memo.*` 키로만 저장합니다. 서버 사용자 식별·권한·업무 검토 저장과는 별개이며 브라우저 데이터를 지우면 삭제됩니다. 저장하지 않은 편집은 페이지를 벗어나면 유지되지 않습니다. 원문 체크도 데모 화면의 상태이며 서버 열람 기록이나 담당자의 실제 업무 확인을 의미하지 않습니다.

## 직접 입력·업종 변경 초안

기업 선택 후 하단의 `직접 입력·업종 변경` 패널에서 사용할 수 있습니다. 직접 입력은 실제 공시 조회 가능성을 확인하는 서버가 없으므로 공시 조회 불가 상황을 가정한 **예시 전용 확인**을 받습니다. 실제 조회 실패나 조회 완료로 기록하지 않습니다.

- 직접 입력: 매출액·영업이익·영업활동현금흐름 3개 예시 항목, 단위 억원(KRW), 출처·유효한 재무 기준일을 입력합니다. 초안에서는 금액을 하나 이상 입력해야 하며, 최종 필수 계정·단위·입력 규격은 아직 확정하지 않았습니다. 음수·소수·세 자리 쉼표를 허용하고 빈칸은 미입력으로 유지합니다. 금액은 문자열로 보존하여 큰 값이나 소수의 반올림을 피합니다.
- 값 비교: 2025년 공통 레이아웃 원본과 직접 입력을 나란히 보여 줍니다. 원본은 선택한 보고서의 자동 수집 결과가 아니며, 값이 달라도 원본이나 분석 화면을 교체하지 않습니다.
- 업종 변경: 변경할 업종·사유·근거가 필수입니다. 초안 이력에 변경 전후 업종·작성 시각·브라우저 데모 사용자를 남깁니다. 실제 변경 권한을 확인하거나 새 분석을 생성한 이력은 아닙니다. 후속 변경 초안의 변경 전 업종은 직전 초안을 기준으로 표시합니다.
- 보관: `loansight.demo.preparation.v1.*` 키에 기업·보고서·회계 범위별로 분리해 저장하며, 이전 초안을 덮어쓰지 않고 추가합니다. 저장하지 않고 닫거나 취소하면 해당 편집은 버립니다. 저장 공간 오류나 잘못된 기존 데이터가 있으면 성공으로 표시하지 않고 입력·기존 데이터를 보존합니다.
- 편집 충돌: 저장 직전 마지막 로컬 초안 ID를 확인하여, 편집 도중 다른 화면에서 저장한 초안이 있으면 저장을 거절하고 편집 내용을 유지합니다. localStorage에는 원자적 트랜잭션이 없으므로 서버의 동시성·권한 검증을 대체하지 않습니다.

저장된 초안은 재무 화면의 값, 분석 ID, 적용 업종 또는 위험 예측에 반영되지 않습니다. 실제 적용은 [직접 입력·업종 변경 설계](../docs/design/01_data-and-analysis.md#input)에 따른 서버 revision과 새 분석 연동 단계에서 진행합니다.

## 다음 연동 범위

5자리 코드 발급/진입·서버 세션, 실제 기업/공시 검색, 수집·분석 요청, 사용자 작업 복원·SSE, 원문 근거 revision, 17항목 원자료, 검토 초안 생성/충돌 처리와 서버 저장은 아직 연결하지 않았습니다. 직접 입력·업종 변경은 위의 로컬 초안 화면까지만 구현했으며, 실제 공시 조회 가능성·자동 수집값 충돌·변경 권한 검증과 입력/변경 revision API·새 분석 생성은 미연동입니다. 뉴스·검증 기록·PDF 확장 화면은 이번 범위에서 제외했습니다. 미정 업무 기준이나 모델 확률을 프론트엔드에서 생성하지 않습니다.

API 연동은 [API·작업 설계](../docs/design/02_api-and-jobs.md), 화면·검토 규칙은 [담당 설계](../docs/design/04_ui-and-review.md)를 따릅니다. 서버 응답 본문의 세부 스키마가 확정되기 전까지 임의 API 응답 계약을 추가하지 않았습니다.

## 검증 기록 · 2026-10-27

- `pnpm build`: TypeScript 검사와 프로덕션 빌드 성공. 기본 500kB를 넘는 번들 안내가 있으며, ECharts 화면은 별도 청크로 지연 로딩합니다.
- `pnpm lint`, `pnpm format:check`: 정적 검사·형식 검사 성공.
- `pnpm test`: 20개 통과. 기존 분석/검토·기업 선택 흐름과 직접 입력·업종 변경의 필수값, 날짜·금액 형식, 큰 금액 보존, 기준별 초안 분리, 취소·초점 복원, 저장 실패·잘못된 기존 데이터 보존, 이전 초안 이력·편집 충돌을 검증합니다. 로딩·오류는 테스트에서만 어댑터 또는 저장 공간을 제어해 재현합니다.
- `pnpm test:e2e`: Chrome PC(1440×1000)·태블릿(820×1180) 6개 통과. 기존 분석/검토·기업 선택 흐름에 더해 직접 입력·업종 변경 폼, 원본/입력값 병기, 미입력 보존, 새로고침 복원, 변경 이력, 취소 후 초점 복원, 기존 분석값 유지와 기간별 초안 격리를 확인합니다. 화면 캡처는 `test-results/`에 생성되며 Git에서는 제외합니다.
- 백엔드·실제 공시·모델·서버 세션·SSE 검사는 실행하지 않았습니다.

도구 구성은 [Vite](https://vite.dev/guide/), [shadcn/ui Vite 안내](https://ui.shadcn.com/docs/installation/vite), [React Router](https://reactrouter.com/start/declarative/installation)를 확인했습니다. 공통 Button은 shadcn/ui의 Slot/CVA 구성을 KB 토큰에 맞췄으며, Dialog는 Radix의 초점 관리·Escape·접근성 동작을 사용합니다.
