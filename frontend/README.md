# LoanSight AI 프론트엔드

React + Vite + TypeScript 기반 화면입니다. 코드 접속·서버 세션·작업 알림은 백엔드에 연결됩니다. 기업 분석은 **가상 기업과 공통 예시 수치**를 사용하며, 실제 분석 결과를 제공하지 않습니다. 백엔드가 없어도 예시 화면을 사용할 수 있습니다.

## 실행

Node.js **24.22.1**과 pnpm **10.34.9**를 사용합니다. 의존성은 `package.json`과 `pnpm-lock.yaml`에 고정했습니다.

Windows에서는 저장소 루트에서 한 번 준비한 뒤 시작할 수 있습니다.

```bat
setup-frontend.cmd
start.cmd --frontend
```

`setup-frontend.cmd`는 `.node-version`에 고정된 Node.js 공식 ZIP을 SHA-256 대조 후 `.tools/`에 풀고, npm으로 `packageManager`에 고정된 pnpm을 같은 디렉터리에 설치합니다. 이어 `pnpm install --frozen-lockfile`을 수행합니다. 최초 준비에는 인터넷 연결과 64비트 Windows(x64/ARM64)가 필요합니다. 사용자/시스템 PATH는 변경하지 않으며 도구 파일은 Git에서 제외합니다. 준비 명령은 다시 실행할 수 있습니다.

`start.cmd`는 프로젝트 전용 도구를 우선 탐색하고, 없으면 PATH의 도구를 사용합니다. Node.js 주 버전과 pnpm 고정 버전을 확인하여 잘못된 버전으로 실행하지 않습니다. 숨겨진 실행 프로세스에도 선택한 도구 경로를 전달합니다. `stop.cmd --frontend`로 종료하고 `start.cmd --frontend --restart`로 재시작합니다. 백엔드도 실행하려면 Docker Desktop을 켠 뒤 `start.cmd`를 사용합니다. 준비 중에는 기존 서버를 종료하지 않으며, 다른 프로그램이 포트를 사용 중이면 시작 시 충돌을 안내합니다.

Node.js와 pnpm을 PATH에 직접 설치한 환경에서는 다음 명령도 사용할 수 있습니다. `.tools/`에만 도구를 준비한 경우 일반 터미널의 `pnpm` 명령은 추가되지 않으므로 위 시작·종료 스크립트를 사용합니다.

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

개발 주소는 `http://127.0.0.1:5173`입니다. PowerShell 실행 정책으로 `pnpm.ps1`이 차단되는 환경에서는 `pnpm.cmd`로 실행합니다.

```sh
pnpm build
pnpm preview
pnpm lint
pnpm format:check
pnpm test
pnpm test:e2e
```

브라우저 테스트는 설치된 Google Chrome을 사용합니다. Chrome이 없다면 설치하거나 `playwright.config.ts`의 브라우저 설정을 개발 환경에 맞게 변경합니다. 빌드 산출물은 `dist/`이며, 운영 서버에서는 SPA 경로를 `index.html`로 fallback해야 합니다. 운영 배포 설정은 이번 범위에 포함하지 않았습니다.

| 화면                | 현재 동작                                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 기업 검색           | 가상 기업 7개, 검색·업종 필터, 대상/복합/미분류/제외 상태와 판정 사유, 보고서·연결/별도 선택                              |
| 직접 입력·업종 변경 | 출처·기준일·변경 사유·근거를 검증하는 초안 폼, 예시 원본과 입력값 비교, 브라우저 저장·복원·이력                           |
| 공통 셸             | KB 색상 토큰, 반응형 메뉴, 선택 전 분석 메뉴 비활성, 출처/예시 표시, 작업 안내 Dialog, 공통 로딩/자료 없음/실패/보류 표시 |
| 재무 요약·실적 변동 | 재무 비율·전기 비교·산식/입력 근거, 리스 예시 옵션, 차입 구성, 워터폴·현금흐름·운전자본 자료 상태, 차트/표 지연 로딩      |
| 주석·위험징후       | 단계·판단 축 필터, 공통 주석 6항목의 검출/검수 상태 분리, 가상 원문·상호 참조, 현재 근거 열람 후 별도 확인                |
| 위험 예측           | 외부 모델·입력 계약·검증 결과 미연동에 따른 보류 표시, 확률 미표시                                                        |
| 담당자 검토         | 예시 확인 3항목, 문단 편집·의견·revision 이력, 템플릿 재적용 2개 모드, 저장 충돌 비교·병합, 근거 포함 복사                |

검색 조건은 URL의 `q`·`industry`, 기업 선택 화면의 분석 기준은 `company`·`report`·`scope`, 분석 화면은 `/analyses/{demo-id}/{section}?report={year}&scope={CFS|OFS}`로 유지합니다. `lease=include|exclude`는 리스부채 예시 옵션이며 기본값은 포함입니다. 재무 비율 묶음은 `ratio`, 위험징후 화면은 `tab`·`severity`·`axis`로 보존합니다. 분석 화면에서 기업 검색으로 돌아가거나 새로고침해도 선택한 기준을 복원합니다. 필터에서 선택 기업이 숨겨져도 우측에 선택과 해제 안내를 유지합니다. 잘못된 기업·보고서·회계 범위·리스 옵션이 URL에 있으면 분석 진입을 막고 기준 초기화를 제공합니다.

예시 7개는 대상 4개, 복합·미분류·제외 각 1개입니다. 제외 기업은 선택 불가이며, 복합·미분류 예시는 실제 업종 근거와 서버의 업종 변경·재분석이 미연동이므로 분석 진입을 보류합니다. 이는 미정인 복합 업종 비중·변경 권한을 확정한 운영 정책이 아닙니다. 미분류에 임의 업종을 배정하거나 제외 예시에 직접 URL로 분석 진입할 수 없습니다.

연도 선택지는 레이아웃 확인을 위한 예시이며 실제 제공 기간을 확정한 정책이 아닙니다. 모든 기업·보고서·회계 범위에서 같은 2023~2025 재무 예시를 사용하므로 선택 조건별 실제 결과로 해석하지 않습니다.

로컬 기록은 서버 사용자 식별·권한·업무 검토 저장과 별개이며 브라우저 데이터를 지우면 삭제됩니다. 저장하지 않은 편집은 페이지를 벗어나면 유지되지 않습니다. 원문 열람·확인 체크도 브라우저 내 예시 기록이며 서버가 검증한 열람이나 담당자의 실제 업무 확인을 의미하지 않습니다.

## 재무·주석 분석 예시

- 재무 비율은 유동성·레버리지·활동성·수익성·성장성으로 나누고 전기/당기·전기 대비 변화·단위·자료 상태를 표시합니다. 산식 창에는 분자/분모·잔액/기간 기준·정밀도·근사/미확보 사유·산식/계정 버전을 제공합니다. 수치는 정적인 산술 예시이며 실제 재무 계산이나 승인된 업무 산식이 아닙니다.
- 차입 구성은 단기·유동성장기·장기·사채·리스와 임대보증금을 구분합니다. 리스 옵션은 부채비율·차입금의존도 예시와 차입 합계를 바꾸고, 관련 검토 기록을 별도 스냅샷으로 분리합니다. 실제 분석 ID 생성이나 입력 옵션 API를 대체하지 않습니다. 예시의 임대보증금은 별도 표시하며 실질 차입 포함 정책은 미정입니다.
- 실적 화면은 영업이익 워터폴, 현금흐름 구성, 영업이익→영업CF 조정과 동일 수치의 표를 제공합니다. 기여분은 회계상 분해이며 경영 원인을 단정하지 않습니다. 회전일수/CCC는 필수 평균 잔액·매출원가 미확보로 계산 불가입니다. 동종·한국은행 비교는 원천/표본 미확보로 보류합니다.
- 위험징후 3건의 경고·주의·관찰은 필터와 확인 흐름을 위한 고정 예시입니다. 운영 임계값이나 실제 평가 결과가 아닙니다. 6개 판단 축 필터, 조건 존재/사유 발생 구분, 규칙/근거 위치를 표시합니다. 업종별 실제 지표·5개년 추세·만기 사다리는 검증된 원천이 없어 자료 없음으로 남깁니다.
- 공통 주석 6항목은 검출/공시상 없음/미검출/추출 실패와 실제 검수 미연동 상태를 구분합니다. 공시상 없음 예시에는 해당사항 없음이 명시된 가상 원문을 연결했습니다. 원문 뷰어에서 교차참조 구간을 열 수 있으며, 확인 버튼을 누른 현재 구간만 로컬 열람 기록에 추가합니다. 다른 구간을 열거나 표시 실패한 구간으로 경고 확인을 해제하지 않습니다. AI 요약은 연결 대기 상태입니다.

## 담당자 확인·검토 초안

위험징후와 담당자 검토 화면은 같은 기업·보고서·회계 범위·리스 옵션·출처/근거 revision의 로컬 확인 기록을 공유합니다. 경고는 해당 근거를 확인한 뒤 체크할 수 있으며, 열람만으로 확인 완료로 바꾸지 않습니다. 체크 해제와 미확인 필터를 제공합니다. 3개 예시 항목은 미정인 17항목 원자료를 대신하지 않으며, 17항목 점검표는 대기 상태입니다.

검토 초안은 핵심 수치·실적 변동·주석 근거·위험징후/예측·추가 확인 문단과 담당자 의견을 분리합니다. `초안 재생성 미리보기`는 AI 호출 없이 고정된 예시 템플릿을 재적용합니다. 수정 문단 유지/자동 초안 영역 전체 교체를 선택하며, 담당자 의견과 저장된 이전 버전은 항상 보존합니다. 재적용 도중 추가 편집이 생기면 결과를 적용하지 않습니다.

`loansight.demo.review.v1.*` 키에 확인 기록과 초안을 따로 보관합니다. 초안에는 생성 원본·편집 텍스트·수정 여부·부모 revision·처리 방식·작성 시각을 남깁니다. 저장 전 마지막 revision을 비교하며 충돌 시 현재 편집을 유지하고, 최신 저장본과 문단/의견별 비교·선택·병합 후 새 revision으로 저장할 수 있습니다. 저장 공간 오류·잘못된 기존 데이터도 덮어쓰지 않습니다. localStorage 비교는 원자적 동시성·서버 소유권 검증을 보장하지 않습니다.

이전 `loansight.demo.memo.*` 메모는 리스 포함 기본 기준에서 기존 값을 읽어 담당자 의견으로 복원합니다. 기존 키를 수정하거나 삭제하지 않으며, 저장부터 새 revision 이력을 사용합니다. 복사본에는 현재 편집·예시 표시·분석 기준·버전·원문 위치·확인 상태를 포함합니다. PDF는 비활성 상태입니다.

## 직접 입력·업종 변경 초안

기업 선택 후 하단의 `직접 입력·업종 변경` 패널에서 사용할 수 있습니다. 직접 입력은 실제 공시 조회 가능성을 확인하는 서버가 없으므로 공시 조회 불가 상황을 가정한 **예시 전용 확인**을 받습니다. 실제 조회 실패나 조회 완료로 기록하지 않습니다.

- 직접 입력: 매출액·영업이익·영업활동현금흐름 3개 예시 항목, 단위 억원(KRW), 출처·유효한 재무 기준일을 입력합니다. 초안에서는 금액을 하나 이상 입력해야 하며, 최종 필수 계정·단위·입력 규격은 아직 확정하지 않았습니다. 음수·소수·세 자리 쉼표를 허용하고 빈칸은 미입력으로 유지합니다. 금액은 문자열로 보존하여 큰 값이나 소수의 반올림을 피합니다.
- 값 비교: 2025년 공통 레이아웃 원본과 직접 입력을 나란히 보여 줍니다. 원본은 선택한 보고서의 자동 수집 결과가 아니며, 값이 달라도 원본이나 분석 화면을 교체하지 않습니다.
- 업종 변경: 변경할 업종·사유·근거가 필수입니다. 초안 이력에 변경 전후 업종·작성 시각·브라우저 데모 사용자를 남깁니다. 실제 변경 권한을 확인하거나 새 분석을 생성한 이력은 아닙니다. 후속 변경 초안의 변경 전 업종은 직전 초안을 기준으로 표시합니다.
- 보관: `loansight.demo.preparation.v1.*` 키에 기업·보고서·회계 범위별로 분리해 저장하며, 이전 초안을 덮어쓰지 않고 추가합니다. 저장하지 않고 닫거나 취소하면 해당 편집은 버립니다. 저장 공간 오류나 잘못된 기존 데이터가 있으면 성공으로 표시하지 않고 입력·기존 데이터를 보존합니다.
- 편집 충돌: 저장 직전 마지막 로컬 초안 ID를 확인하여, 편집 도중 다른 화면에서 저장한 초안이 있으면 저장을 거절하고 편집 내용을 유지합니다. localStorage에는 원자적 트랜잭션이 없으므로 서버의 동시성·권한 검증을 대체하지 않습니다.

저장된 초안은 재무 화면의 값, 분석 ID, 적용 업종 또는 위험 예측에 반영되지 않습니다. 실제 적용은 [직접 입력·업종 변경 설계](../docs/design/01_data-and-analysis.md#input)에 따른 서버 revision과 새 분석 연동 단계에서 진행합니다.

## 다음 연동 범위

실제 기업/공시 검색, 수집·분석 요청, 서버 원문 열람/근거 revision·17항목 원자료, 실제 LLM 요약/검토 초안 생성과 서버 저장·충돌 처리는 아직 연결하지 않았습니다. 직접 입력·업종 변경은 위의 로컬 초안 화면까지만 구현했으며, 실제 공시 조회 가능성·자동 수집값 충돌·변경 권한 검증과 입력/변경 revision API·새 분석 생성은 미연동입니다. 뉴스·검증 기록·PDF 확장 화면은 이번 범위에서 제외했습니다. 미정 업무 기준이나 모델 확률을 프론트엔드에서 생성하지 않습니다.

API 연동은 [API·작업 설계](../docs/design/02_api-and-jobs.md), 화면·검토 규칙은 [담당 설계](../docs/design/04_ui-and-review.md)를 따릅니다. 현재 연동은 기존 identity/tasks 라우터의 실제 응답 계약을 사용합니다.

## 서버 세션·작업 연동

루트에서 `start.cmd`로 양쪽 서버를 시작하고, 상단 **코드로 접속**에서 새 코드를 발급하거나 발급된 5자리 코드로 재접속합니다. 코드 앞의 0을 보존합니다. 사용자 버튼에서 다른 코드로 전환하거나 현재 기기에서 로그아웃할 수 있습니다. 발급 코드를 보관해야 같은 사용자로 다시 접속할 수 있으며, 코드를 아는 사람은 같은 작업에 접근할 수 있습니다.

상단 **내 분석 작업**은 진행 중/미확인 종료 수를 나누어 표시합니다. 목록에서 상태·단계·갱신 시각·상세 결과를 확인하고 종료 알림을 서버에 확인 처리합니다. **연결 점검 실행**만 명시적으로 새 작업을 만들며 실제 재무 분석은 수행하지 않습니다. 응답 유실 후 재시도는 같은 점검 키를 사용합니다. 작업 상세는 조회 시점의 결과이며, 새로고침·화면 이동은 작업을 재실행하지 않습니다.

앱 공통 Provider가 서버 목록과 cursor를 받은 후 탭당 SSE 하나를 연결합니다. 중복 cursor·이전 상태 버전을 무시하고 `reset`은 목록 재조회 후 새 cursor로 구독합니다. 네트워크 단절은 같은 EventSource의 기본 재연결을 사용하며 복구 중에는 마지막 상태임을 알립니다. 연결이 종료되면 **목록 다시 불러오기**로 재시도할 수 있습니다. 사용자 전환·로그아웃·만료 시 이전 요청·연결·서버 캐시를 정리합니다. 다른 탭의 세션 변경은 BroadcastChannel로 재확인하며, SSE 오류 및 창 포커스 복귀 시에도 세션을 검증합니다. 브라우저 저장소에는 세션 토큰·코드를 저장하지 않습니다.

기업 분석·원문 열람·검토 메모와 직접 입력 초안은 기존 브라우저 예시입니다. 서버 사용자별 업무 저장이 아니며 사용자 코드 전환으로 분리되지 않습니다.

Vite는 상대 경로 `/api`를 `http://127.0.0.1:8000`으로 프록시합니다. `LOANSIGHT_API_PORT`로 백엔드 포트를 변경할 수 있습니다. Origin을 그대로 전달하므로 프론트 주소를 백엔드 `LOANSIGHT_ALLOWED_ORIGINS`에 등록해야 합니다(기본 Compose에 localhost/127.0.0.1 프론트 주소 포함). 프론트 접속 호스트를 바꾸면 쿠키가 분리됩니다. 운영 배포에서도 같은 출처의 `/api` 프록시, SSE 버퍼링 해제와 HTTPS 쿠키 설정이 필요합니다. `pnpm preview`와 운영 프록시 구성은 이번 범위에 포함하지 않습니다.

개발중, Cloudflare Named Tunnel의 공개 주소는 `https://kb-bridge.sjw-project.site`이며, 같은 Windows에서 실행하는 터널의 서비스 대상은 `http://127.0.0.1:5173`입니다. Vite는 해당 호스트를 명시적으로 허용합니다. Compose 기본 허용 출처에도 공개 주소를 포함하며, `backend/.env`에 `LOANSIGHT_ALLOWED_ORIGINS`가 있으면 기본값을 덮어쓰므로 해당 목록에도 공개 주소를 추가해야 합니다. 백엔드 환경변수 변경은 API 컨테이너를 재생성해야 반영됩니다.

현재 연동 검증은 [세션·작업 UI 검증 기록](../docs/reviews/04_frontend-session-task-validation.md)에서 관리합니다. EventSource 재연결·Last-Event-ID 동작은 [HTML 표준](https://html.spec.whatwg.org/multipage/server-sent-events.html)을 따릅니다.

## 예시 화면 초기 검증 기록 · 2026-10-27

- `pnpm build`: TypeScript 검사와 프로덕션 빌드 성공. 기본 500kB를 넘는 번들 안내가 있으며, ECharts 화면은 별도 청크로 지연 로딩합니다.
- `pnpm lint`, `pnpm format:check`: 정적 검사·형식 검사 성공.
- `pnpm test`: 32개 통과. 기존 기업 선택/입력 흐름에 더해 산식 근거·리스 옵션·현금흐름·미확보 표시, 위험징후 필터·주석 검출 상태·잘못된 원문 열람 차단, 기준/근거 revision별 확인 격리, 수정 문단/의견 보존, 생성 중 새 편집 보호, 저장 충돌 비교·병합, 이전 메모 복원·복사본 근거·잘못된 저장 데이터 보호를 검증합니다. 로딩·오류·진행 중 편집은 테스트에서 어댑터나 저장 공간을 제어해 재현합니다.
- `pnpm test:e2e`: Chrome PC(1440×1000)·태블릿(820×1180) 10개 통과. 기존 기업 선택/입력 흐름과 재무→현금흐름→주석→담당자 검토 이동, 실제 차트/표, 리스 옵션, 다른 원문으로 경고 확인 불가, 문단 유지/전체 재적용, 의견·이력·새로고침 복원, 클립보드의 근거/버전 포함, 두 탭 저장 충돌·병합과 옵션별 기록 격리를 확인합니다. 화면 캡처는 `test-results/`에 생성되며 Git에서는 제외합니다. 긴 편집 흐름을 위해 테스트별 60초·동시 worker 2개로 실행합니다.
- 위 초기 예시 화면 검증에서는 백엔드·실제 공시·모델·서버 세션·SSE 검사를 실행하지 않았습니다. 이후 서버 연동 검증은 [별도 기록](../docs/reviews/04_frontend-session-task-validation.md)을 참고합니다.

도구 구성은 [Vite](https://vite.dev/guide/), [shadcn/ui Vite 안내](https://ui.shadcn.com/docs/installation/vite), [React Router](https://reactrouter.com/start/declarative/installation)를 확인했습니다. 공통 Button은 shadcn/ui의 Slot/CVA 구성을 KB 토큰에 맞췄으며, Dialog는 Radix의 초점 관리·Escape·접근성 동작을 사용합니다.
