## 프론트엔드 구성

React + TypeScript + Vite를 기반으로 다음 도구를 사용한다. 관련 라이브러리와 제공 컴포넌트를 우선 활용하고, 화면설계서의 KB 색상·정보 밀도·숫자 정렬에 맞춰 조정한다. 버전은 프로젝트 초기화 시 호환성을 확인해 고정한다.

| 영역 | 도구 | 적용 |
|---|---|---|
| 라우팅 | React Router | 화면 이동·분석 ID/조회 조건의 URL 관리 |
| 스타일 | Tailwind CSS | 반응형 레이아웃·공통 디자인 토큰 |
| UI 컴포넌트 | [shadcn/ui](https://ui.shadcn.com/docs/installation/vite) | 버튼·입력·탭·Dialog/Sheet·Popover·배지·로딩 등 |
| 서버 상태 | TanStack Query | API 조회·캐시·SSE 이벤트에 따른 갱신 |
| 데이터 테이블 | [TanStack Table](https://tanstack.com/table/v8/docs/introduction) | 재무표 정렬·필터·페이지 처리, 표시는 공통 UI로 구성 |
| 차트 | [Apache ECharts](https://echarts.apache.org/en/feature.html) | 추세·워터폴·만기 사다리·불릿·업종 위치의 공통 차트 |
| 폼·검증 | [React Hook Form](https://react-hook-form.com/get-started) + [Zod](https://zod.dev/) | 코드·직접 입력·메모의 폼 상태와 입력 검증 |
| 기능 아이콘 | [Lucide React](https://lucide.dev/guide/react/getting-started) | 검색·복사·펼치기 등 조작 의미가 있는 아이콘 |
| HTTP·진행 알림 | 브라우저 fetch·EventSource | 동일 출처 세션 쿠키로 REST·SSE 연결 |
| 화면 상태 | URL·React Context·useState | 선택 기준·세션 컨텍스트·팝업 상태 |
| 코드 품질 | ESLint·Prettier | 정적 검사·형식 통일 |
| 테스트 | [Vitest](https://vitest.dev/guide/)·[React Testing Library](https://testing-library.com/docs/react-testing-library/intro/)·[Playwright](https://playwright.dev/docs/intro) | 단위/컴포넌트·주요 사용자 흐름 검증 |

컴포넌트별 의존성은 실제 사용하는 기능에 맞춰 추가한다. 프론트엔드 입력 검증과 별개로 서버가 입력·권한을 검증하고 재무 계산·최종 판정을 수행한다. 패키지 관리는 [프로젝트 구조·배포 설계](05_project-and-deployment.md#structure)를 따른다.

## 공통 UI·뉴스

- 앱 진입 시 현재 세션을 조회한다. 세션이 없으면 `새 코드 발급` 또는 `기존 코드 입력`을 제공한다. 코드 입력은 앞의 0을 보존하는 텍스트 필드에 숫자 키패드·최대 5자·명시적 제출을 사용한다. GNB에 현재 사용자 코드와 전환/로그아웃을 표시한다.
- 세션 복원/코드 진입 후 내 작업·메모를 조회하고 SSE를 연결한다. 사용자 전환·세션 만료 시 이전 연결과 캐시를 정리한다. 코드/세션 규칙은 [사용자 식별](05_project-and-deployment.md#identity)을 따른다.
- React 공통 셸은 기업/기간/회계 범위/적용 업종·출처 revision을 유지한다. 기업 미선택 시 기업 검색 외 분석 메뉴를 비활성으로 하고, 변경 시 이전 조건의 Query/화면을 혼합하지 않는다. GNB는 사용자 작업 알림을 표시한다.
- 출처 칩은 기업명·종목코드/시장·업종/세부분류·수동 변경·보고서·CFS/OFS·결산월·재무 기준일·접수번호·수집일을 표시한다. 예측 공시일과 재무 기준일은 각각 표시한다.
- 경고/주의/관찰은 색+텍스트, 단계 없음은 정상으로 표시하지 않는다. 자료 상태·검출·검수·모델 검증·담당자 확인·GNB 알림 확인을 구분한다. 로딩/자료 없음/조회 실패와 재시도·직접 입력 안내를 제공하고 실패를 0으로 표시하지 않는다.
- 화면설계서의 KB Yellow Positive #FFBC00, KB Gray #60584C, KB Yellow Negative #FFCC00, 배경 #F3F4F1, 잉크 #15181D, 경고 #B42318·주의 #9A5B06·관찰 #355C86을 공통 토큰으로 정의한다. 고정폭 숫자 정렬, 팝업 외 과한 그림자·그라데이션/글로우/장식 아이콘 제외, PC/태블릿 반응형을 적용한다.
- 뉴스 구현 시 N-F12는 기간/매체/항목 필터, 관련성 검수 상태·기사 시각/실적 귀속 기간·원문 링크·동명이인/단순 언급/중복 제외 사유를 보관한다. 수집/품질 검증이 어려우면 링크 전용 모드로 제공하고 누락 가능성을 표시한다. 미검수 기사는 검수 완료 기사와 명확히 구분하며 실적 원인을 단정하지 않는다.

GNB 진행 알림은 [API·작업 처리 설계](02_api-and-jobs.md#gnb), 사용자별 접근 전제는 [식별·접근 범위](05_project-and-deployment.md#identity)를 따른다.

## 담당자 체크·원문 열람·초안 revision

대응: N-F21~23/N-F34/N-F37, PDF 7·11쪽. 담당: review·risk·evidence.

- `POST /api/v1/reviews`는 코드 진입 후 서버 세션의 사용자/Workspace와 허용된 analysis_run_id에 검토를 만들거나 기존 검토를 반환한다. `GET /analyses/{id}/review-context`는 그 검토 ID·규칙 제안·23개 RISK 후보·열람/확인 상태와 근거를 반환한다.
- review_item은 review/분석·규칙·근거 revision·판정 방식(자동/원문/외부 확인)·시스템 제안·담당자 확인 상태·변경 revision을 가진다. 미확인/확인 완료와 위험 해당 여부는 별도로 유지한다.
- 원문 뷰어가 해당 구간을 정상 표시한 뒤 `POST /reviews/{reviewId}/evidence-views`로 열람 사실을 기록한다. 서버는 인증 사용자·분석·경고·원문 구간·근거 revision의 관계와 접근 권한을 검증하고 시각·근거 해시를 남긴다. 기록은 실제 내용을 이해·검증했다는 증명이 아니다.
- `PUT /reviews/{reviewId}/items/{itemId}`는 기반 revision과 체크/해제를 받는다. 경고를 확인 완료로 바꿀 때 해당 사용자의 현재 근거 revision 열람이 없으면 거부한다. 다른 사용자·다른 분석·이전 근거의 열람으로 대체하지 않는다.
- 새 분석/근거로 바뀌면 이전 검토는 보존하고 새 경고 확인을 미확인으로 시작한다. 업무 확인을 GNB 알림 acknowledgement로 완료하지 않는다. 시스템의 추천도 체크를 자동 완료하지 않는다.
- `review_draft_revision`은 기반 분석/규칙/모델·근거·문단 ID·생성 원본·사용자 수정 여부·편집 내용·부모 revision·담당자 의견을 보존한다. `GET/PUT /reviews/{reviewId}/draft`로 조회·저장한다.
- `POST /reviews/{reviewId}/draft-regenerations`는 기반 revision과 수정 문단 유지/전체 재생성 선택을 받는다. 긴 생성은 같은 MQ·Worker 체계의 작업 종류로 처리하며 analysis_run_id·review_id를 연결한다. GNB는 작업 종류와 해당 검토 화면 링크를 표시한다.
- 수정 문단 유지 모드는 사용자 수정 문단과 담당자 의견을 보존하고 생성 가능 영역만 갱신한다. 전체 재생성은 선택한 자동 초안 영역을 교체하되 담당자 의견과 이전 이력은 보호한다. 갱신되지 않은 수정 문단에는 기반 분석·출처가 바뀌었는지 표시해 수동 재검토하게 한다.
- 저장과 비동기 생성 완료 시 서버가 기반 revision을 비교한다. 최신 편집이 있으면 409 Conflict로 충돌/재조회·병합을 요구하고 덮어쓰지 않는다. 재생성 재시도에도 고유 요청 ID로 중복 적용을 막는다. 권한·보존 기간·최종 UX 승인은 N-U08에서 확정한다.
- 복사본에는 핵심 수치·변동·주석·위험징후/예측·추가 확인·업종/산식/규칙/모델 버전·접수번호/원문 위치를 유지한다. 검증되지 않은 확률은 복사본에도 넣지 않는다. PDF 버튼은 초기 비활성으로 유지한다.

## 화면 설계 반영 상태

문서 기준은 기획안 v2.2·요구사항 v0.0.6·PRD/기능명세서 v0.0.5·WBS v1.3다. Figma 실제 v0.0.1 섹션은 보존했으며 실제 v0.0.2 복제/편집은 Starter MCP 도구 호출 한도로 미완료다. 코드 저장소의 색상 변경 PDF는 의미상 v0.0.1 보관본이며 최신 기획의 화면 반영 완료본이 아니다.
