추가 통계·업종/기업 확대, PDF·지점 운영은 N-F28~29의 확장이다.

덤프의 선택 원천 적재와 기존 구조화 결과를 두 화면에 결합하는 구현·확장 계획은
[덤프 주석 통합 계획](07_dump-evidence-integration.md)을 따른다. OFS 재무 CSV 적용과
주석·위험징후·예측 근거 연동의 완료 범위는 구분한다.

**권장 구현 순서:** 먼저 실제 기업의 사업보고서 한 건을 **수집 → 정규화 → 재무지표 → 주석 근거 → 규칙 판정 → 화면 조회**까지 관통하는 수직 기능으로 구현한다. 이후 대상 4개 업종 내 적용 범위와 모델 기능을 확장한다. 추가 업종 도입은 별도 범위 변경으로 검토한다.

현재 4단계의 구조화 기반으로 [`dart-note-hierarchy` v0.8.4 wheel](../../backend/app/modules/dart_note_hierarchy-0.8.4-py3-none-any.whl)을 uv/이미지에 등록하고 준비된 HTML의 API 접수→Worker→원문 구간 저장·JSON 조회까지 연결했다. 이후 사실 검수와 규칙 입력 실행기를 추가했으며, 4단계 전체 완료와는 구분한다. 상태와 후속 순서는 다음과 같다.

1. **구현:** 준비된 연결·별도 HTML·문서 정보 접수, 원문 바이트/해시 보존, 공개 `DocumentProcessor` Worker 호출, [원문 구간 저장](01_data-and-analysis.md#note-storage)과 소유권 제한 조회.
2. **구현:** 선택한 접수번호의 DART 원본 ZIP/XML·목차와 연결/별도 주석 뷰어 HTML을 보존하고 기존 구조화 작업에 연결한다. 정확한 목차를 확인할 수 없으면 보류하며 검증 범위를 임의로 확대하지 않는다. 계약은 [DART 원문 자동 수집](../../backend/README.md#dart-원문-자동-수집), 실제 자료 검증은 [수집·구조화 검증](../reviews/11_dart-document-collection-validation.md)을 따른다. 사용자 제출 HTML은 여전히 별도 출처이며 정정 전후 비교·원문 변경 자동 감지는 후속이다.
3. **부분 구현:** 저장된 계층·구간과 정제한 원문 열람본을 프론트에 연결했다. 목차·검색·표 필터와 구간 강조·URL 복원을 제공한다. [조회 계약](../../backend/README.md#note-import-api)과 [화면 검증](../reviews/12_note-results-view-validation.md)을 따르며 일반 교차참조 이동은 후속이며, 통합 묶음의 사실별 열람·검수는 별도 구현했다.
   **검색 기반 구현:** [키워드 도구 기반 근거 탐색 설계](03_ai-integration.md#evidence-search)에 따라 목차·다중 검색·문맥 읽기 도구와 공통 6항목 기본 검색의 DB 저장·후보 표시를 연결했다. [구현 계약](../../backend/README.md#note-search-api)과 [Codex 보완 탐색](../../backend/README.md#note-agent)을 따른다. 담당자 사실 검수 저장은 통합 묶음에서 구현했고 OpenAI API 어댑터·검토 메모 서버 저장은 후속이다. 초기 벡터 검색·로컬 모델은 필수가 아니다.
4. **구현·후속 구분:** 통합 사실 추출 경로·원문 열람/검수 이력·규칙 입력 실행기는 연결했다. 실제 추출 품질 평가·운영 규칙 등록·분석 revision 통합은 후속이다. 모듈 회귀 테스트와 추출 품질·업무 승인 검증을 구분하고 미정인 합격 기준은 확정하지 않는다.

wheel에는 원본 모듈의 테스트·평가 workflows가 포함되지 않는다. 패키지 원본 저장소의 회귀/데이터셋 검증과 이 저장소의 설치·API·Worker 통합 검증을 구분한다. 설치·실행 방법은 [백엔드 안내](../../backend/README.md#note-hierarchy), 원천/정답지 기반 검수 기록은 아래 기준을 따른다.
