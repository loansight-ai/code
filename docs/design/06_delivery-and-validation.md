## 단계별 개발 순서

| 단계 | 구현 범위 | 검증 목표 |
|---|---|---|
| **1. 프로젝트 골격** | React, FastAPI, PostgreSQL, 5자리 코드 발급·세션, RabbitMQ, Worker·Relay, Compose, k3s 기본 매니페스트 | 사용자 코드/세션·소유 범위와 Outbox→MQ→Worker→DB→SSE 기본 흐름 확인 |
| **2. 수집·저장** | 기업/업종 판정·수동 변경, 직접 입력, 보고서 선택, DART 과거 보고서 보존·정규화 | N-F01~04/30, 출처·revision·자동/수동 충돌·회계 범위 재현 |
| **3. 재무 MVP·필수 비교** | 공통 산식·계정 사전, N-S02·03, 3개년 비교·한국은행 참고 통계, 분석 캐시·GNB 복원 | 중복 조회 방지, 비교군/통계 차이·입력 옵션 일치, 사용자별 조회·복원 |
| **4. 주석·규칙** | N-S04-1·04-2, 원문 구간/참조·검수, 6개 축·업종 우선 지표·5개년·만기 차트 | 근거 추적, 검수 전 입력 차단, 결측/조건 존재와 실제 사건 구분 |
| **5. 검토 흐름** | N-S07, 17항목·원문 열람 게이트·초안 편집/복사/저장·재생성 충돌 | 분석/사용자/근거 revision 격리·편집 보존 |
| **6. AI 요약** | LLM Gateway, Codex/API Adapter, 4구역 요약·검토 초안 연결 | 공급자 교체 시 동일 계약, 검증된 수치/근거 사용·사용자 의견 보호 |
| **7. 외부 모델 연동·추론** | Predictor Port, 제공 모델 파일/API·입력 스키마·검증 보고서·설명 결과 연동 | 버전/입력 호환성·타임아웃·보류 처리, 제공된 결과와 화면 일치 |
| **8. 검증 기록 정리·보완** | 단계별 정답지·계정 확보·추출 품질·외부 모델 보고서 통합, 사용자 비교 실험, N-S08 표현 결정, 뉴스 보완·PWA 검토 | 저장소 검증 기록과 외부 보고서 구분, 뉴스는 초기 예측 입력에서 제외 |

검증 기록은 해당 단계부터 수집하고 8단계에서 정리한다. 업무 단계 번호는 수직 MVP 이후의 확장 순서이며 필수 기능의 생략을 뜻하지 않는다. 추가 통계·업종/기업 확대, PDF 출력·지점 운영은 N-F28~29의 별도 확장 범위다.

**권장 구현 순서:** 먼저 실제 기업의 사업보고서 한 건을 **수집 → 정규화 → 재무지표 → 주석 근거 → 규칙 판정 → 화면 조회**까지 관통하는 수직 기능으로 구현한다. 이후 대상 4개 업종 내 적용 범위와 모델 기능을 확장한다. 추가 업종 도입은 별도 범위 변경으로 검토한다.

현재 4단계의 구조화 기반으로 [`dart-note-hierarchy` v0.8.4 wheel](../../backend/app/modules/dart_note_hierarchy-0.8.4-py3-none-any.whl)을 uv/이미지에 등록하고 준비된 HTML의 API 접수→Worker→원문 구간 저장·JSON 조회까지 연결했다. 이는 주석 사실 추출·검수나 4단계 전체 완료를 뜻하지 않는다. 상태와 후속 순서는 다음과 같다.

1. **구현:** 준비된 연결·별도 HTML·문서 정보 접수, 원문 바이트/해시 보존, 공개 `DocumentProcessor` Worker 호출, [원문 구간 저장](01_data-and-analysis.md#note-storage)과 소유권 제한 조회.
2. **후속:** DART 자동 수집·보고서에서 주석 HTML 분리, 정정 관계와 공식 원천 revision 연결. 현재 제출 metadata를 공식 확인 정보로 취급하지 않는다.
3. **후속:** 저장된 계층·구간을 프론트 원문 뷰어에 연결하고 원문 정제·하이라이트·교차참조·열람 기록을 구현한다.
4. **후속:** 대표 원문 대조로 구조·부분 관계·표 기간 대응을 검수하고, 항목별 사실 추출·검수·위험규칙을 별도로 연결한다. 모듈 회귀 테스트와 추출 품질·업무 승인 검증을 구분하고 미정인 합격 기준은 확정하지 않는다.

wheel에는 원본 모듈의 테스트·평가 workflows가 포함되지 않는다. 패키지 원본 저장소의 회귀/데이터셋 검증과 이 저장소의 설치·API·Worker 통합 검증을 구분한다. 설치·실행 방법은 [백엔드 안내](../../backend/README.md#note-hierarchy), 원천/정답지 기반 검수 기록은 아래 기준을 따른다.

- 15곳 기능/5곳 정답지는 논의 중이다. 인용된 40개사 추출 시트는 기존 기획 근거이며 현 검수 실적이 아니다. 계정 확보 업종별 5곳 이상 계획과 모델 표본은 별도 목적이다. 표본 기업과 합격 기준은 미정이다.
- 미검출 원인은 규칙 누락/공시 없음/형식 차이를 구분하고 공시 없음은 원문 대조 후에만 기록한다. 건설 분양률/미분양·임대 후속사건·제조 담보·도소매 점포의 보완 근거를 추적한다.
- `POST/GET /api/v1/validation/runs`, `POST/GET /validation/gold-cases`, `POST/GET /validation/account-coverage`, `POST/GET /validation/user-experiments`를 내부 역할 범위에서 제공한다. 하위 결과·원기록은 실행 ID와 원천 버전으로 입력/수입·조회한다. 외부 모델 보고서는 출처/버전을 유지해 별도 수입·조회한다.
- N-S08은 기록 API를 이용하는 내부 페이지 또는 내부 산출물로 표현할 수 있다. 표현·접근 권한의 최종 결정이 미정이어도 기록 업무를 생략하지 않는다. 측정 전은 측정 전/null로 반환하며 참여 인원·시간 단축 등 성과를 미리 채우지 않는다.
- 사용자 실험의 과제 난이도·순서·인원·조건과 한계를 공개하고 측정 결과를 은행 전체 효과로 일반화하지 않는다. 데이터 확보·추출 검수·외부 모델 연동·운영 완료를 각각 기록한다.
