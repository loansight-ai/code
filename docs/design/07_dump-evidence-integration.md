## 목표와 현재 상태

`loansight_ofs_20261031.dump`의 필요한 공시 자료만 선택 적재하고, 기존 HTML 구조화·추출
결과와 함께 검색·열람할 수 있게 한다. 일차 대상 화면은 **주석·위험징후**와 **위험 사건
예측**이다. 재무 누락값 보완은 이 근거 계층을 사용하는 후속 기능으로 둔다.

계획 수립 당시 OFS 재무·사건·조회 범위 CSV만 적재돼 있었으나, 현재는 시범 보고서 4건의
주석·사업보고서 구간·감사의견 선택 적재와 통합 사실 검수·규칙 입력까지 연결했다. 기존 주석은 Workspace에 속한
SourceArtifact / NoteStructure / SourceSegment로 저장된다. 검색·Codex 도구·화면 진입이
structure_id에 묶여 있으며, 표 검증과 원문 뷰어는 실제 HTML·XPath에 의존한다.
예측 화면에는 사건 후보·조회 범위가 연결돼 있지만 위험규칙 전체와 모델 추론은 미연동이다.

이 계획은 원천 결합·검색·근거 표시를 먼저 완성한다. 위험 임계값·모델 특징·예측 대상·
담당자 승인 정책은 기존 설계와 외부 제공 명세를 따르며 여기서 새로 확정하지 않는다.

## 저장과 선택 적재

현재 PostgreSQL 인스턴스에 서비스 DB와 별도의 원천 DB를 두는 구성을 제안한다.
DB명 예시는 loansight_source이며 구현 때 기존 DB 존재 여부를 확인한다. 원천 DB의
적재 계정과 읽기 계정을 분리하고, 서비스 요청은 서비스 DB의 정규화된 공시 근거를
조회한다. 원천 DB 직접 접속 권한을 사용자나 에이전트에 주지 않는다.

| 구분 | 원천 | 보존 내용·선택 조건 |
|---|---|---|
| 1차 필수 | public.report | 선택한 기업의 관련 보고서 식별·기간·공시일·정정 정보·원래 수집 상태 |
| 1차 필수 | public.note_section | 선택 보고서의 OFS 주석 전체. 본문·표 JSON·단위·캡션·순서·source를 보존 |
| 1차 필수 | public.doc_section | 같은 보고서의 사업보고서 구간. 계층·제목·본문·표·body_skipped를 함께 보존 |
| 1차 필수 | public.audit_opinion | 관련 감사의견·계속기업 후보와 본문/첨부 근거·일치 여부·원래 fs·상태 |
| 후속 보조 | public.note_fill / fs4_note_applied | 기존 수치 후보·적용/보류 사유. 새 검증의 탐색 단서로 사용 |
| 후속 검토 | public.note_item | 원문 발췌와 기간·금액 역할 등 유용한 후보. 직접 구간 연결과 회계 범위가 검증되기 전에는 확정 입력으로 사용하지 않음 |

service.* 복사 테이블, 모든 뷰·구체화 뷰, 대량 fs_line / fs_source, 모델·리뷰 테이블은
초기 대상에서 제외한다. risk_event / event_coverage는 이미 서비스에 적재한 버전을
재사용한다. 감사 API 원문이 실제 대조에 필요한지 확인한 후 audit_api 추가 여부를 정한다.

선택 적재의 단위는 **기업·보고서 목록**이다. 첫 시범 기업/보고서 목록은 인벤토리 결과로
정하고 파일에 명시한다. 기존 HTML과 덤프가 모두 있는 사례, 덤프만 있는 사례,
재무가 없지만 사건·공시가 있는 사례를 포함한다. 최근 몇 년·재무 보유 기업만으로
범위를 임의로 제한하지 않는다. 검증 후 명시한 대상 기업·보고서로 확대한다.

주석을 검색어 일치 행만 잘라 저장하지 않는다. 선택한 문서의 OFS 주석 본문·표 문맥을
함께 보존한다. doc_section은 회사 공통 영역일 수 있으며 audit_opinion.fs도 원래 값을
검토해야 하므로 이 둘에 OFS를 일괄 부여하지 않는다. 범위 미확인은 그대로 남긴다.

원천 테이블명과 기존 서비스의 동명 테이블을 혼용하지 않는다. 네 테이블만 복원하더라도
FK·시퀀스 등 필요한 의존 객체를 목록화한다. 행 필터가 필요한 자료는 COPY 스트림을
읽어 선택 목록으로 거른 후 적재한다. 전체 DB 복원이나 모든 구체화 뷰 계산은 하지 않는다.

## 공통 근거 계층

기존 HTML 결과와 덤프 원천을 같은 물리 구조로 가장하지 않고, 두 어댑터가 공통 읽기
계약을 제공하도록 한다. 명칭은 구현 시 조정 가능하며 아래는 논리 단위다.

| 논리 단위 | 책임 |
|---|---|
| 원천 적재 버전 | 덤프 식별·선택 목록·선택 추출물 해시·행 수·수집 기준일·적재 상태·어댑터 버전 |
| 공시 근거 문서 | 기업·접수번호·결산기간·문서 영역·원래 회계 범위·출처·공개 가용 시각과 확인 상태 |
| 근거 구간 | 주석/장 제목·계층·문서 순서·본문 또는 표·불변 원천 참조·내용 해시·처리 한계 |
| 보고서별 근거 묶음 | Workspace와 기업·보고서에 고정된 자료 집합. 기존 structure revision과 덤프 문서 revision을 명시적으로 연결 |
| 추출 사실 후보 | 항목·기간·금액 역할·방향·단위·근거·검출 상태·검증/검수 상태·충돌 관계 |

공개 덤프 원천은 공통 저장하고, 기존 업로드 원문·사용자 탐색·검수 기록은 Workspace
권한을 유지한다. 기존 structure_id를 조회할 때와 동일하게 소유권을 확인한다. 다른
사용자의 업로드가 같은 기업·접수번호를 주장한다는 이유로 자동 합류시키지 않는다.

결합 조건은 기업·접수번호·기간·회계 범위와 문서 영역이다. 같은 회사·연도만으로
정정본이나 CFS/OFS를 합치지 않는다. 회사 공통 구간은 별도 영역/범위로 표시하고
회사 전체 근거와 특정 재무제표의 수치를 구분한다.

묶음은 구성 문서 revision 목록과 해시를 고정한다. 새 덤프·정정본·파서 변경은 새 버전으로
만들고 기존 분석·검색·검수 결과의 참조를 바꾸지 않는다. 정규화 이후에도 원래 표/행 ID와
원천 테이블 정보를 남긴다.

### 인용 위치와 중복

- 기존 HTML 인용은 structure revision·segment ID·실제 XPath를 유지한다.
- 덤프 인용은 적재 버전·원천 테이블/행 ID·표 seq·저장된 행/열 또는 JSON 위치를 사용한다.
  실제 원본에 없는 XPath·병합 정보를 만들어 넣지 않는다.
- 같은 보고서의 동일 텍스트/표 후보는 화면에서 묶을 수 있으나 두 출처 참조를 모두 보존한다.
  같은 숫자라는 이유만으로 다른 기간·부분 금액·한도·잔액을 같은 사실로 합치지 않는다.
- 수치가 다르면 충돌을 표시한다. 원천 선택 우선순위나 금액 허용 오차를 임의로 정하지 않는다.
- note_item은 직접 구간 연결 ID가 비어 있으므로 제목·발췌를 탐색 단서로 삼고 해당 구간을
  재확인한다. 주석 번호만 맞는 연결을 검증된 근거로 기록하지 않는다.

## 구현 순서와 완료 기준

1~4단계는 시범 보고서 4건 범위에서 연결했고, 5단계는 사실 검수·규칙 입력 실행기까지
구현했다. 운영 규칙 등록·예측 시점/모델 연결과 6단계의 CSV 수치 자동 보완·대상 확대는
후속이다. 아래 완료 기준은 각 단계의 확장·인수 기준으로 남긴다.

### 1. 인벤토리와 시범 선택 목록

대상 네 테이블의 전체 크기와 선택 후 행 수·내용 바이트를 스트리밍으로 산출한다.
report와의 연결 누락·중복, 실제 fs 값, 빈/생략 본문, 표 JSON 형식·짧은 행·다단 헤더를
검사한다. 주석이 없는 영역과 실제 검색 불가능 영역을 구분한다. 알려진 접수번호 중복과
원천에 없는 fs4_report_flag도 별도 이슈로 남긴다.

**완료 기준:** 선택 목록·선택 사유·행 수·용량·연결 오류·범위 미확인 목록을 재현할 수 있다.
이 결과를 확인하기 전에는 전체 원천 적재나 복원 용량을 확정하지 않는다.

### 2. 선택 원천 적재와 정상화

별도 원천 DB에 필요한 스키마·의존 객체를 준비하고 선택 행만 적재한다. 불변 파일 또는
JSON 추출물 해시와 원래 행 식별자를 기록한다. 부분 적재는 활성 버전으로 노출하지 않고,
검증 완료 시 서비스 정규화 작업이 사용할 버전을 확정한다. 동일 내용의 재실행은 재사용하고
새 내용은 새 버전으로 보존한다.

덤프 어댑터로 본문·표·감사의견 후보를 공통 읽기 계약에 연결한다. 기존 SourceArtifact /
NoteStructure / SourceSegment를 덮어쓰거나 가짜 HTML 파싱 작업을 생성하지 않는다.
큰 자료의 청크 적재·재시작 체크포인트와 완료 상태를 관리하고, 원문 내용·인증정보를 작업
로그에 대량 출력하지 않는다. 기존 Outbox·Worker·SSE 실행 기반은 필요한 비동기 작업에
재사용한다.

**완료 기준:** 재실행 중복 없음, 중단 후 재개 가능, 미완료 버전 비노출, 기존 DB·분석·원문
보존, 원천 행 → 정규화 구간 역추적 가능.

### 3. 근거 묶음과 통합 검색

현재 NoteSearchTools의 목차·키워드 검색·문맥 조회를 원천 어댑터 뒤로 분리한다. 기존
structure_id용 API는 유지하고, 보고서별 근거 묶음을 대상으로 하는 경로를 추가한다.
공통 6항목 사전은 재사용하되 미확보 영역을 실제 가용 데이터로 계산한다. doc_section
테이블이 존재하더라도 body_skipped거나 비어 있는 영역을 검색 완료로 표시하지 않는다.

도구 응답은 단일 source_sha256 가정 대신 묶음 revision과 후보별 원천 revision을
검증할 수 있어야 한다. Codex에는 고정된 묶음의 허용 도구만 제공하고 실제 읽은 구간의
인용인지 확인한다. 인용 검사는 문자열·원천 일치와 의미 검증을 분리한다.

**완료 기준:** HTML만/덤프만/둘 다 있는 보고서에서 6항목 검색·문맥·인용 검증이 동일한
권한 경계를 지키며 동작하고, 결과별 출처와 검색 범위가 확인된다.

### 4. 두 화면과 진입 경로 연결 — 첫 제공 범위

기존 NoteResultsPage / useNoteWorkspace의 structure_id 전용 주소를 유지하고, 보고서
선택·재무 결과·기존 주석 결과에서 통합 근거 묶음으로 진입하도록 확장했다. 현재 주소는
`/reports/:corpCode/:receiptNo/:scope/evidence|prediction`에서 묶음을 연 뒤
`/evidence/:bundleId/evidence|prediction`으로 이동한다. 근거 API는
`/api/v1/me/evidence-bundles/{id}` 아래에 있다. 구조화 HTML이나 재무 분석이 없어도
덤프가 선택 적재된 보고서는 같은 묶음의 원문을 조회한다.

| 화면 | 첫 제공 범위 |
|---|---|
| 주석·위험징후 | 추출 현황·선택 근거·보증/만기/소송 집계·PF 만기 사다리. 통합 목차·검색·사실 검수는 펼쳐서 사용 |
| 위험 사건 예측 | 기존 사건 이력/조회 범위 + 같은 기준의 주석 근거와 입력 준비/보류 상태 |

덤프 본문·표는 '덤프 추출 본문/표'로 렌더링한다. 실제 HTML 원본 열람과 구분하고,
저장된 cells의 불규칙 행·누락된 병합 정보·미확인 기간을 그대로 표시한다. 원문에 없는
표 좌표 대응을 확정하지 않는다. 프론트 캐시는 Workspace·묶음 revision·원천 종류를
포함하고 사용자/기업/버전 전환 시 이전 내용이 남지 않게 한다.

**완료 기준:** 구조화 HTML이 없는 기업·보고서에서도 두 메뉴에 진입할 수 있고, 기존
HTML과 덤프의 근거를 함께 열며 출처·미확보·충돌 상태가 일치한다. 자료가 있다고
위험징후 판정이나 모델 확률이 이미 제공된 것으로 표시하지 않는다.

### 5. 사실 후보 검증과 현재 위험징후·예측 입력 연결

기존 추출 후보와 새 검색 결과를 근거에 연결하고 금액 역할·제공/수취·원고/피고·
당기/전기·기간·통화·단위를 검증한다. 기존 규칙상 0과 대시 변환 0은 명시적 공시 0과
구분한다. 현행 의미 검수·위험규칙·모델 입력 게이트는
[데이터·분석](01_data-and-analysis.md#evidence)과
[외부 모델 계약](03_ai-integration.md#prediction)을 따른다.

위험징후 규칙이 제공·확정된 항목부터 평가하고, 미정 임계값은 후보 근거 표시 상태로
유지한다. 예측 입력은 공시 공개 가용 시각과 정정본을 기준일에 맞게 제한한다. 공개 시각이
확인되지 않은 자료를 추정 시각으로 통과시키지 않는다. 회사 전체 사건 이력 표시와
예측 시점에 이용 가능한 입력을 구분한다.

**완료 기준:** 검출·자동 검증·담당자 검수·규칙 평가·모델 입력 가능 상태가 구분되고,
미검수·미확보·시점 부적합 자료가 확정 사실이나 예측 확률로 승격되지 않는다.
실제 모델 추론은 제공 모델/manifest·입력 계약이 있을 때 별도 연동한다. 모델 학습은 제외한다.

### 6. 수치 보완과 대상 확대

공통 근거 계층을 기존 financial.enrichment에 연결한다. CSV 누락 사유와 검증되지 않은
0의 재검토를 구분하고, HTML 표/덤프 표 각각에 맞는 셀 검증기를 사용한다. 현재 검증기의
raw_table_html·병합 좌표 전제를 덤프에 그대로 적용하지 않는다. 확정된 직접 금액만
기존 계산기로 재계산하고 기본 재무·과거 분석은 보존한다.

**완료 기준:** 보완값에서 실제 출처·기간·단위·표 위치를 열 수 있고 기존 확정값의 충돌을
덮어쓰지 않는다. 첫 제공 범위의 정확도·비용·지연 결과로 기업·보고서 확대를 결정한다.

## 검증과 인수

기존 테스트를 확장하며 구현을 그대로 따라 쓰는 검사 대신 실제 실패 경계를 검증한다.

- **적재:** 필요한 의존 객체만 선택, 행 필터/해시/정밀 금액 보존, 재실행·중단 복구,
  미완료 버전 비노출, 기존 데이터 불변. DB 검사는 별도 _test DB의 격리 스키마에서 수행.
- **권한·결합:** 다른 Workspace 자료 차단, 사용자 업로드 출처 구분, 정정본·회계 범위·
  문서 영역의 잘못된 연결 거부, 회사 공통 영역과 범위 미확인 상태 유지.
- **검색·인용:** 6항목 검색, 번호 없는 본문·표·다단 헤더·불규칙 행, 생략 본문·문맥 잘림,
  후보별 원천/인용 일치, 중복 출처 보존, 상충 사실 표시.
- **화면:** 기존 주소·원문 강조 회귀, 덤프만/혼합 원천/재무 없는 기업 진입,
  사용자·기업·버전 전환, 추출 본문과 HTML 원본 표시 구분.
- **판정·예측:** 후보를 사건 발생으로 오인하지 않음, 미검수·규칙상 0·자료 부족·미정 규칙
  처리, 기준일 이후 공시/정정본 배제, 모델 미제공 시 확률 보류.
- **실제 표본:** 공통 6항목의 정답 구간과 대조해 누락·오탐·연결 정확도·처리 시간·저장량을
  기록. 측정 전 복구율·검색 합격률·운영 호출 예산·기간을 임의로 확정하지 않음.
