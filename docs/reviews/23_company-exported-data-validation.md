# 수집 CSV 적재·기업 연결 검증

검증일: 2026-10-30. 적재 방식과 CLI 계약은
[백엔드 안내](../../backend/README.md#collected-company-data)에서 관리한다.

## 범위

실제 폴더 `backend/data/company/exported/`의 세 CSV를 수집 스냅샷으로 적재했다.
기존 기업 원장에는 외래키로 연결하고, 보고서 접수번호·사업연도·CFS/OFS를 보존한다.
원문 HTML/XML이나 담당자 검수 결과를 생성하지 않는다. 기존 재무 분석·프론트 화면의
입력으로 자동 채택하는 기능과 업종 통계 생성은 이번 변경에 포함하지 않았다.

## 실행 결과

- Python 표준 라이브러리 CSV 검사: 재무 18,417행, 사건 2,698행, 조회 범위 2,271행.
- PostgreSQL 테스트 DB `loansight_test`: 전체 Alembic 마이그레이션 적용 성공.
- 신규 검사 9건 통과: 정밀 금액·0/null·코드·줄바꿈 보존, 키/형식/후보 수 검증,
  회계 범위 구분, 버전 보존, 재적재, 동시 적재, 원장 누락 거부, 트랜잭션 롤백.
  DB 테스트는 테스트별 격리 스키마를 생성·정리했다.
- 전체 pytest: API 키 환경변수를 제거한 환경에서 119 passed, 63 skipped,
  13 subtests passed. 선택적 DB/외부 연동 검사는 전체 실행에서 생략됐다.
  신규 PostgreSQL 검사 4건은 위 별도 실행에서 모두 통과했다.
- 최초 전체 pytest 실행에서는 Compose가 주입한 API 키/빈 API 키 변수 때문에
  기업 검색·dotenv 검사 2건이 실패했다. 제품 코드를 변경하지 않고 해당 키의
  환경변수를 제거해 재실행했다.

## 실행 환경과 협업 상태

호스트는 Python 3.14이며 프로젝트의 지원 버전은 3.12다. 실제 DB 검증·전체 pytest는
기존 백엔드 이미지의 Python 3.12.15와 lockfile 기반 의존성을 사용했다.
새 코드는 호스트 소스를 마운트한 일회성 Compose 컨테이너로 실행했다.
기존 API/Worker/Relay 컨테이너를 교체하거나 새 코드를 배포하지 않았다.

작업 브랜치는 `feat/import-company-exported-data`다. 현재 환경에 GitHub CLI가 없어
Issue/PR 생성과 번호 연결은 수행하지 않았다. 변경은 주제별 로컬 커밋으로 분리하며
원격 푸시는 수행하지 않았다.
