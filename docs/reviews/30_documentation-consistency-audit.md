# 문서 전체 정합성 점검

점검일: 2026-11-01 (Asia/Seoul). 현재 구현은
[현행 상태표](../design/06_delivery-and-validation.md#current-status), 근거 데이터의 상세 계약은
[통합 근거 안내](../../backend/data/evidence/README.md)에서 관리한다.

## 점검 범위와 수정

점검 시작 시 저장소의 Markdown 52개를 대상으로 로컬 링크·앵커를 검사하고, 루트/백엔드/
프론트 README와 설계 01~07, 데이터 안내, 관련 검증 기록의 현재 상태 표현을 코드와 대조했다.
과거 검증 기록의 날짜·검사 수·당시 한계는 현재 검사 결과로 덮어쓰지 않았다. 이 기록을
추가한 뒤 문서 전체를 다시 검사했다. Git 제외 `.run/` 개인 메모와 외부 기획 원문의 내용
전체는 정합성 판정 대상에 포함하지 않았다.

|---|---|

현행 상태는 개발·제공 동작 계획 한 곳에 모으고, 상세 설명은 담당 계약으로 연결했다.
아키텍처 v0.3/v0.4와 과거 테스트 결과는 보존했다. 설계 표의 Tenacity는 현재 의존성에
없다는 점도 명시했다. 운영 임계값이나 승인 정책을 새로 확정하지 않았다.

## 확인 방법과 한계

- Markdown의 상대 링크와 명시적/제목 앵커를 검사했다. 깨진 로컬 참조를 수정하고 새
  현행 상태·참고 기준·검증 기록 링크를 포함해 재검사했다. 외부 URL 접근 가능성은 이번
  점검에서 전수 확인하지 않았다.
  최종 검사 대상은 이 기록을 포함한 53개 문서·347개 로컬 참조이며, 누락 경로/앵커는 0개다.
- 실행 중인 로컬 API의 OpenAPI에서 근거 목록·묶음·검색/문맥·사실 검수·추출·signals의
  경로와 메서드를 확인했다. 목표 `/analyses/{id}/signals`와 실제
  `/api/v1/me/evidence-bundles/{bundle_id}/signals`가 다름을 문서에 표시했다.
- 파서/재무 보완·규칙 registry/service·런타임 설정·프론트 router/보고서 링크 컴포넌트,
  패키지와 데이터 manifest를 대조했다. 운영 registry가 빈 상태이며 실제 Codex 호출은
  사용자 선택으로 보류된 사실을 유지했다. 인증정보를 복사하거나 모델을 호출하지 않았다.
- 문서 변경에 대해 공백 오류와 로컬 참조를 검증했다. 애플리케이션 코드를 바꾸지 않았으므로
  단위/통합 테스트·빌드·DB 검증을 새로 실행하지 않았다. 앞선 실행 결과는
  [규칙 입력 검증](29_risk-inputs-and-live-extraction-validation.md), 메뉴 스타일 변경 시
  실행한 빌드/ESLint·기업 화면 13개 검사는 해당 변경의 검증 범위로 구분한다.

## 남은 확인

참고 지표·단계 기준을 실제 규칙 ID·버전·대상 업종·기간·원천 필드에 매핑하고 승인/검증한
뒤 registry에 등록해야 한다. 문서 점검만으로 운영 판정이나 기획 전체 전환을 완료한 것은
아니다. 실제 Codex 추출 평가, 덤프를 통한 CSV 누락값 자동 보완과 예측 모델/공개 시점
연결도 현재 미완료 범위로 유지한다.

## 후속 최신화

위 점검 이후 추출 현황·보증/만기/소송·PF 만기 사다리와 핵심 비율 상대 구간이 추가됐다.
이 문서의 53개·347개 참조 수는 최초 점검 당시 기록이다. 최근 구현을 반영한 현행 상태와
전체 참조 재검사 결과는 [문서 최신화 검증](36_documentation-current-state-validation.md)을 따른다.
