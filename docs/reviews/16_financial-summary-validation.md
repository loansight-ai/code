# 핵심 재무 요약·공통 재무 저장 검증

> 2026-10-29 · 구현 및 실제 공시 검증

실제 기업·보고서 선택에서 재무 API 수집·기존 XML/주석 HTML 수집기 재사용·계정 매핑·PostgreSQL 저장·Worker 완료·요약 화면 조회까지 연결했다. 데이터 계약·보존 경로·산식과 미정 정책은 [백엔드 재무 계약](../../backend/README.md#financial-api), 사용 흐름은 [프론트 안내](../../frontend/README.md#financial-summary)에서 관리한다.

## 검증 범위와 결과

| 검증 | 기대 결과 | 실제 결과 |
|---|---|---|
| 백엔드 비통합 테스트 | 원문·기업·재무·Worker 회귀 확인 | 89 통과, 실제 Codex CLI handshake 1개는 환경 변수 미설정으로 건너뜀 |
| 재무 DB 통합·마이그레이션 | 실제 PostgreSQL 임시 스키마에서 저장·권한·모델 일치 | 재무 흐름 3개와 upgrade/check/downgrade 1개 통과 |
| 프론트 테스트 | 기존 화면 회귀와 재무 조회·옵션 변경·오류 처리 | 13파일 76개 통과 |
| 브라우저 | 데스크톱/태블릿 요약·산식 창·메뉴·리스 변경·가로 넘침 | Chrome 2개 통과, 화면 캡처 생성 |
| 정적 검사·빌드 | Python/TypeScript/ESLint 검사와 프로덕션 빌드 | Ruff·TypeScript·ESLint·Vite 통과. Vite의 큰 청크 경고는 남음 |
| 실제 API 응답 | 4기업 OFS/CFS를 구분해 수집 | 8개 조건 확인. 롯데리츠 CFS는 상태 013으로 값 없음 |
| 실제 원문 | 기존 수집기로 XML/ZIP·OFS HTML 보존, 이자비용 보완 | 4기업 모두 단위·기간·계정·합계가 확인된 표에서 이자비용 확보 |
| 로컬 전체 작업 흐름 | HTTP→Outbox→RabbitMQ→Worker→DB→결과/원본 조회 | 4기업 OFS 작업 모두 SUCCEEDED, 원본 JSON 다운로드 모두 200 |
| 실제 브라우저·프록시 | 모의 응답 없이 로그인·기업 선택·분석 요청·저장 결과·산식 확인 | 5174에서 오뚜기 실데이터 흐름 확인, 브라우저 오류 0 |

통합 검사는 `loansight_test` DB의 임시 스키마를 사용했다. 기존 개발 DB 볼륨은 삭제하지 않았다. 로컬 Compose에도 추가 마이그레이션과 새 API·Worker 이미지를 반영하고 건강 상태를 확인했다.

기존 5173 포트는 관리되지 않는 다른 프로세스가 사용 중이어서 그대로 두고 이 브랜치의 프론트를 `http://localhost:5174`에 실행했다. 로컬 전용 `.run/financial-compose.override.json`은 API의 기존 허용 Origin을 유지하며 localhost/127.0.0.1의 5174만 추가한다. 기존 `.env`·공개 호스트 허용값은 수정하지 않았다. 기본 Compose만으로 재생성하면 이 임시 override는 적용되지 않으므로 같은 미리보기를 유지하려면 두 파일을 함께 지정한다. 실제 화면 캡처는 `.run/financial-validation/financial-summary-live.png`에 남겼다.

## 확인한 예외와 보존 동작

- 표준 ID가 같고 이름이 다른 경우는 연결하며, 표준 ID가 다른 넓은 합계 계정을 좁은 구성 계정으로 바꾸지 않는다.
- 실제 0·미기재·대시·중복 충돌·다른 통화를 구분한다. 숫자의 쉼표 형식·정밀도를 검사한다.
- 손익계산서와 포괄손익계산서 중복은 명시한 우선순위로 처리한다. 영업이익과 CF 이자 지급을 이자비용으로 혼용하지 않는다.
- 주석은 당기/전기 열뿐 아니라 기간별 별도 표, 병합 셀과 합계 열을 처리한다. 금융원가 전체로 이자비용을 근사하지 않는다.
- 음수 손익 기여분만으로 양수 비용을 생성하지 않는다. 별도 양수 비용 표가 존재하고 금액이 일치하는 경우만 부호 표현 차이를 대조한다.
- 다른 정정 접수번호·기업·회계 범위가 반환되면 저장/계산을 중단한다.
- 주석 수집 실패가 이미 확보한 정형 재무값의 저장을 막지 않는다.
- 동일 요청·메시지 중복은 원천값과 완료 이벤트를 중복 생성하지 않는다. 리스 옵션·refresh key 변경은 별도 분석으로 보존한다.
- 다른 Workspace는 결과와 원본 다운로드 모두 404다. 브라우저에서 다른 분석을 로딩하거나 새 조건을 요청하는 동안 이전 값을 표시하지 않는다.
- 원천값은 Decimal/Numeric, 지표·증감·OP 분해는 서버 계산으로 유지한다. 브라우저는 표시 단위·차트 좌표 변환만 수행한다.

main에 포함된 시장 필터 인자와 기존 기업 검색 테스트 대역의 서명이 달랐던 부분도 회귀 검증 중 맞췄다. 실제 시장 필터 동작을 테스트용 단순 Catalog에 추가한 것은 아니다.

산식 창 디자인 보완 시 실데이터·예시 공통 표와 상태 배지를 적용하고 관련 프론트 테스트 16개를 재검증했다. 실제 데이터의 Chrome 화면에서 PC·태블릿·모바일 너비, 가로 넘침 없음, Escape 닫기와 원래 버튼 초점 복원, 보류 사유 표시를 확인했다. 캡처는 `.run/financial-validation/formula-{desktop,tablet,mobile}.png`에 저장했다.

## 제공 한계

- 추세는 선택한 공시의 3개 비교기간이다. 별도 과거 공시를 연도별로 수집한 5개년 계열이나 리츠의 연간 재구성을 완료한 것은 아니다.
- 롯데리츠는 현행 원장의 세부 업종 미확정으로 `industry:null`이다. 재무값은 제공하고 업종 강조는 미확정으로 표시한다. 테스트 기업 지정만으로 분류·서비스 편입을 확정하지 않았다.
- 평균잔액·기간 일수·첫해·EBITDA·CAPEX·현금보상·금융비용 범위 정책은 임의 확정하지 않는다. 총자산영업이익률 등 해당 지표는 사유와 함께 보류한다.
- 차입 합계의 구성 금액이 빠진 경우 합산을 보류한다. 미공시 사채·유동성 대체 금액을 0으로 간주하지 않는다.
- 상세 PF·만기·평균금리, 동종 비교군·한국은행 참고 통계, 위험규칙·모델 추론은 현재 확정 결과를 제공하지 않는다.
- XML은 기존 수집기로 원본을 보존한다. 현재 수치 보완기는 회계 범위가 확인된 HTML 주석 표에 한정하며 범용 XML 수치 해석이나 모든 복잡한 표의 의미 추론을 보장하지 않는다.
- 이 기능의 자동 표 검증은 담당자의 사실 검수·승인과 구분한다. 기존 검수 전 키워드/Codex 후보를 확정 수치로 바로 사용하지 않는다.
- 로컬 변경은 테스트 보정·재무 백엔드·산식 창·화면 연결·문서로 나누어 커밋한다. 원격 Issue/PR 생성은 수행하지 않았으며 이 환경에는 GitHub CLI가 없다.
