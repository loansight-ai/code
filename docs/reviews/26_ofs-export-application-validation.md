## 적용

`loansight_ofs_20261031.dump`의 public.fs4_report / fs4_value를 선택적으로 읽어
mv_fs4_wide_ok와 같은 상태 필터의 130열 CSV를 생성했다. 재무 18,394행 전부 OFS이며,
사건 2,698행·조회 범위 2,271행도 덤프의 public 테이블에서 생성했다. 전체 덤프를
복원하지 않았다. 제품 코드·DB 스키마·산식·회계 범위 기본값은 변경하지 않았다.

이전 CSV 3개와 설명서는 `backend/data/company/exported/archive/20261030/`에
보존했다. 이동 전후 작업 파일 SHA-256과 Git 정규화 콘텐츠의 일치를 확인했다.
새 파일 SHA-256은 [manifest](../../backend/data/company/exported/manifest_20261101.json)에
기록하고 실제 파일과 다시 대조했다.

## 실제 API·Worker 흐름

현대건설(00164478), 접수번호 20260318001395, 2025 사업연도로 확인했다.

- 공개 collected-data API에서 버전 생략 시 새 적재 ID를 선택하고 available_scopes는
  OFS만 반환했다. OFS 재무 1행·최근 5개년 이력 5행을 반환하며 이력도 전부 OFS다.
- 같은 새 버전에서 CFS 요청은 재무 0행이다. 이전 적재 ID를 명시하면 기존 CFS 1행을
  계속 조회할 수 있다. CFS를 조용히 OFS로 대체하거나 옛 버전을 자동 선택하지 않는다.
- 검증용 새 사용자 세션에서 scope와 source_import_id를 모두 생략해 기존 재무 분석
  API를 호출했다. 기본 OFS와 새 적재 ID가 자동 선택·고정됐다.
- 실제 Relay → RabbitMQ → Worker → DB 완료를 거쳐 SUCCEEDED가 됐다.
  분석 ID는 41017058-d597-4bd5-9cf9-d929c25f4d4c다.
- 매출 16,512,462,000,000원·자산총계 17,191,283,000,000원이 새 OFS CSV와 정확히
  일치했다. 지표 39개를 반환했고 원천 JSON의 import_id도 새 적재 ID와 일치했다.
- 사용자 코드·쿠키는 출력하거나 기록하지 않았고 검증 세션은 종료했다.

## 범위와 한계

이번 작업은 OFS 재무 입력 전환이다. 주석 구조화 결과·표 셀·근거 연결을 서비스에
추가 적재하거나 누락값을 새로 추출하는 작업은 포함하지 않았다. 원천의 규칙상 0과
미검수 상태는 새 버전에서도 그대로이며, 해당 의미는 데이터 설명서에서 관리한다.

전환 후 새 분석은 최신 데이터 버전을 사용한다. 과거 분석 URL은 원래 버전에 고정돼
유지된다. 기존 분석 화면을 새 OFS 값으로 바꾸려면 기업·보고서에서 OFS 기준으로
새 분석을 시작해야 한다. 주석 보완 옵션·명시적 재수집의 OpenDART 경로는 유지한다.

실제 브라우저 시각 검수, 프론트 전체 회귀, 전체 덤프 복원 검사는 수행하지 않았다.
작업 브랜치는 data/ofs-export-20261101이며 Issue/PR 생성·커밋·원격 푸시는 수행하지
않았다. 서비스 변경은 기존 로컬 Compose 환경에만 적용했다.
