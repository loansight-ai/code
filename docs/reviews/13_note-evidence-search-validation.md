# 주석 검색 도구·공통 6항목 기본 검색 검증

검증일: 2026-10-29. 브랜치 `feat/note-evidence-search`. 사용자가 지정한 이번 범위는 도구와 기본 검색이며 Codex/OpenAI API 호출은 포함하지 않는다. 실제 계약은 [검색 구현 안내](../../backend/README.md#note-search-api), 전체 흐름은 [AI 연동 설계](../design/03_ai-integration.md#evidence-search)에서 관리한다.

## 구현 범위

목차 조회·다중 키워드 검색·앞뒤 문맥/표 읽기 도구와 공급자 중립 JSON Schema·허용 목록 디스패치를 구현했다. 기존 저장 데이터와 PostgreSQL을 사용하며 검색은 SQL 필터·정렬·페이지 제한으로 실행한다. 공통 6항목 기본 검색은 Workspace와 구조화 revision·사전/도구 버전에 맞춰 DB에 저장·재사용한다. 결과 화면에서 항목별 후보 조회·추가 조회·원문 이동·새로고침 복원을 제공한다.

## 확인한 검사

- 백엔드 전체 pytest: 102개 통과·5개 건너뜀. 마이그레이션 upgrade·모델 일치·downgrade 포함. 이후 표 문맥의 저장 구간 ID 연결과 본문 페이지 위치 검사를 추가해 관련 단위/통합 6개를 재검사했다.
- Ruff 검사 통과. 프론트 Vitest 66개 통과·ESLint 통과·TypeScript/Vite 빌드 통과. 기존 번들 크기 안내는 남아 있다.
- 검색: ANY/ALL, 띄어쓰기 정규화, 리터럴 `%`, 본문/목차/표 제목/표 문맥, root 직속·부모 미확정·자식 목차, 후보 페이지의 중복 방지·빈 결과, 과도하거나 허용되지 않은 인자 거부.
- 문맥: 다른 목차 경계 표시, 본문 위치 페이지, 표 행 페이지·명시적 헤더·병합 셀·추정되지 않은 td 헤더·앞쪽 행 보존, 원시 HTML 미반환, 같은 revision의 실제 구간·발췌 인용 검사와 잘못된 인용 거부.
- 권한·저장: 다른 Workspace의 도구/저장 결과 조회 차단, 허용되지 않은 Origin 거부, 6항목 모두 실행, 동시 요청의 동일 결과 재사용, AI 미실행/검수 전·미확보 영역 보존.
- 화면: 저장 결과 복원, 원문 선택 이벤트, 다른 원문 해시의 응답 거부, 추가 페이지 오류 후 첫 결과 보존·재시도 확인.

## 실제 보고서 연결

뉴트리 `01214248`, 접수번호 `20260320001416`의 2025.12 사업보고서를 실제 Compose·RabbitMQ·Worker로 새 검증 사용자에게 연결했다. Chrome PC 1440×1000 별도(OFS), 태블릿 820×1180 연결(CFS) E2E 2개가 통과했다. 기본 검색의 6항목 표시, 차입 관련 후보 5개에서 10개로 추가 조회, 후보의 원문 위치 이동, 기존 표 필터·강조·새로고침 후 저장 결과 복원·가로 넘침 없음을 확인했다. 화면 캡처를 검토했으며 사용자 코드는 캡처에서 가렸다. 캡처·실행 로그는 Git 제외 경로에 보관한다.

## 검증 한계

실제 보고서의 검색 연결을 확인한 것이며 정답 구간 전체 대조에 따른 재현율·정밀도나 회계 사실 정확도를 검증한 것은 아니다. 사전은 초기 초안이고 단순 일치 후보 수는 위험 건수가 아니다. 현재 검색 범위는 재무제표 주석이므로 외부감사·신용평가 등 다른 장은 미확보로 남긴다. 시점 적합 예측 검색, 전체 보고서 영역 확장, LLM 보완 탐색·호출 이력, 사실 추출·검수 저장은 후속이다. 동시 사용자 부하·CPU/RAM 상한·검색 지연의 운영 기준은 측정·확정하지 않았다.
