# 핵심 재무 요약 시각화 개선안 검증

- 검증일: 2026-10-30
- 작업: [Issue #21](https://github.com/loansight-ai/code/issues/21)
- 브랜치: `feat/21-visual-financial-summary`
- 근거: [업종별 지표 문서](../03_업종별_핵심재무지표_상환연체위험징후지표_v0.0.3.md), 사용자 제공 N-S02 수정안 이미지. Claude 링크 본문은 접근하지 못했으며 첨부 이미지를 검토했다.

## 구현 범위

사용자가 확정한 시각화 화면을 `/financials/:financialId/summary`의 기본 화면으로 사용한다. 이전 `summary-preview`는 분석 ID와 쿼리를 보존해 기본 주소로 이동한다. 예시 전용 `/examples/financial-summary`는 가상 건설 기업의 정적 데이터로 로그인 없이 배치를 확인하며 기존 `/preview/financial-summary`도 이 주소로 연결한다. 실제 분석 경로는 기존 세션·Workspace별 조회·오류/진행 상태·주석 보완·리스 변경 계약을 재사용한다. 서버 코드와 계산 스냅샷은 변경하지 않았다.

영업이익·이익률 차트, 전기/당기 핵심 5개 비율 막대, 5축 업종 백분위 레이더와 영역별 백분위 위치 막대, 업종별 지표 표, 검산 가능한 차입 구성 막대를 제공한다. 5개 영역은 3개년 추세가 아니라 업종 내 위치를 표현한다. 산식 창의 입력값·출처와 닫기 후 초점 복원을 유지한다. 원천 계정은 펼쳐서 조회한다.

## 검증 결과

기본 화면 확정 후 전체 프론트 단위 검사 14개 파일 94개, 재무 요약·시각화 브라우저 검사 6개, TypeScript·전체 ESLint·프로덕션 빌드를 통과했다. 기존 개선안 주소의 리다이렉트와 쿼리 보존, 기본 요약에서 산식·현금흐름 이동·리스 변경을 확인했다. 이전 요약 전용 컴포넌트를 제거하고 원천 계정·주석 소계·검산 근거·산식 조회를 새 화면의 펼침 영역에 유지했다.

| 방법 | 기대 결과 | 실제 결과 |
|---|---|---|
| TypeScript `tsc -b` | 타입 오류 없음 | 통과 |
| ESLint 전체 검사 | 오류 없음 | 통과 |
| Vitest: visual-summary, financial-summary, live-workspace | 원천/산식·결측·키보드·리스 변경·기존 화면 회귀 확인 | 3개 파일 21개 통과 |
| Playwright: visual-summary, financial-summary | 데스크톱 1440px·태블릿 820px의 예시 및 실제 분석 경로, 기존 요약·산식·리스 요청 확인 | 6개 통과. 실제 분석 API는 고정 응답으로 검증 |
| 각 예시 E2E에서 390px로 변경 | 페이지 전체 가로 넘침 없음 | 통과 |
| Vite production build | 배포 산출물 생성 | 통과. 500kB 초과 청크 경고 있음 |

최초 독립 포트의 E2E 실행은 종료 단계에서 멈춰 중단했으며 통과로 집계하지 않았다. 이후 기존 5173 개발 서버를 재사용해 완료했다. 셸에 예시 배지를 추가한 뒤 테스트의 중복 텍스트 선택을 범위 지정으로 수정하고 6개를 다시 통과했다. 예시 헤더와 390px 스크린샷 추가 후 해당 예시 검사 2개도 통과했다. 스크린샷은 `frontend/test-results/visual-summary-*/`에 생성되며 Git에는 포함하지 않는다.

## 데이터 해석과 남은 범위

- 핵심 5개 비율의 막대는 지표별 전기·당기의 0 기준 크기 비교다. 5개 영역은 별도로 업종 백분위를 표시한다. 레이더는 Apache ECharts를 사용하며 축 순서는 탭과 시계 방향으로 대응한다. 위치 막대는 0~100%, 중앙값 50% 점선, 회사 위치 점·채움과 상위/하위 텍스트를 제공한다. 낮을수록 취약하도록 지표의 유불리 방향을 보정한 비교값을 입력받는다.
- 예시 경로만 가상 분포·영역 집계값을 제공한다. 실제 경로는 비교군·산식 정책을 확보하기 전까지 백분위·영역 점수를 만들지 않는다. 업종·기간·회계 범위가 다른 비교값과 유효 범위 밖 백분위는 표시하지 않는다. 단일 지표라도 비교 불가이면 보류 사유를 유지한다. 비교 메타데이터와 영역 점수 산출은 후속 서버 작업이다.
- 업종 미확정은 업종별 목록을 임의 선택하지 않는다. 회전율 대신 현재 제공되는 회전일수를 명시하며, 서버에 없는 항목은 산식·원천 연결 필요로 표시한다.
- 차입 비중은 모든 구성 값이 확정·비음수이고 서버 합계와 일치할 때만 표시한다. 부족한 항목을 0으로 채우지 않는다. 단기차입과 1년 내 만기는 구분한다.
- 미정 산식과 미확보 계정은 기존 자료 상태·보류 사유를 따른다. 영업CF가 음수여도 기존 서버의 유효한 비율을 임의로 폐기하지 않는다.
- 업종 중앙값·분위·PF/만기·EBITDA/CAPEX 정책과 신규 지표의 실제 산출은 후속 서버/데이터 작업이다. 이번 검증은 실제 DART 재수집·DB 저장·외부 모델 검증을 포함하지 않는다.
- 실적 변동·현금흐름 탭의 개선은 이번 범위에 포함하지 않는다.

## 업종 백분위 영역 수정 검증

사용자가 제공한 5축 균형·업종 위치 화면에 맞춰 기존 영역 내 3개년 추세를 제거했다. 단위 검사 `visual-summary`·`financial-summary` 2개 파일 21개와 데스크톱·태블릿 E2E `visual-summary` 4개, 타입·대상 ESLint·프로덕션 빌드를 통과했다. 문맥 불일치 차단, 백분위 미확보 처리, 탭 목록 변경과 레이더 축 이름 클릭에 의한 탭 전환을 확인하고 `industry-position.png`를 생성해 배치·색상을 검토했다. 빌드의 500kB 초과 청크 경고는 유지된다.

## 업종 핵심 지표·상환능력 배치 수정

건설업 표는 계약자산 증가율 차이·공사미수금 회수기간·공사원가율·PF/자본·영업CF/유동부채의 5개 행을 당기·업종·상태 열로 표시한다. 상환능력은 차입 구성과 4개 상환 지표 표를 좌우로 배치하며 좁은 화면에서는 위아래로 바꾼다. 예시 경로는 제공 이미지의 비교값·상태 배지·추가 비율을 명시적 예시로 표시한다. 실제 분석에는 예시 값·위험 단계를 적용하지 않는다.

차입 표시는 단기(유동 리스 포함)·유동성장기/유동성사채·장기(비유동 리스 포함)·비유동사채로 묶고 원천 항목을 펼쳐 확인한다. 전체 구성과 서버 총액이 일치할 때만 막대를 표시한다. 예시의 총액 18,950억원과 1년 내 만기 9,300억원은 가상 데이터다. 실제 분석의 1년 내 만기는 정형 차입금만으로 추정하지 않는다. 예시 토글은 고정·비활성이며 실제 토글은 기존 서버 재분석을 요청한다. 영업CF가 음수이면 요약 행에는 비율 대신 현금 금액과 보류 상태를 표시하며, 서버 산식·저장 결과는 변경하지 않는다.

`industry-highlights.png`, `repayment-highlights.png`를 생성해 배치·색상을 검토했다. 관련 단위 21개, 브라우저 4개, 타입·대상 ESLint·빌드를 검증했다.
