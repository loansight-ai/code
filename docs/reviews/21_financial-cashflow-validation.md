# 실적 변동·현금흐름 시각화 검증

2026-10-30 · 실제 결과 경로 `/financials/:financialId/cashflow`

## 적용 내용

- 기존 ECharts 공통 컴포넌트로 영업이익 변동 분해와 기간별 영업이익·영업활동현금흐름을 나란히 표시한다. 좁은 화면에서는 세로로 배치한다.
- 합계는 진한 회갈색, 증가는 연한 회갈색, 감소는 연분홍, 음수 현금흐름은 빨간색이다. 영업이익 분해의 증가·감소는 원인 추정이 아닌 회계상 증감을 뜻한다.
- 실제 결과 API의 `profit_bridge`, 원천 계정과 비교기간을 사용한다. 백엔드·저장 스냅샷·계산 정책 변경은 없다.
- 분해 금액은 원 단위 소수 여섯 자리까지 정수로 변환해 전기 영업이익과 증감 합계가 당기 영업이익에 일치하는지 검산한다. 누락·불일치 시 차트를 보류한다. 차트는 0을 넘나드는 증감도 표시한다.
- 현금흐름 차트는 실제 비교기간 수와 회계 범위를 표시하고 결측을 0으로 채우지 않는다. 이전 현금흐름이 확인된 비음수일 때만 음수 전환으로 설명한다. 표시기간 모두의 이익이 양수일 때만 모두 흑자로 설명한다.
- CFS/OFS 상대 범위 데이터는 현재 결과에 없으므로 비교 스위치는 비활성 상태와 사유를 표시한다.
- 금액·자료 상태와 검산 표는 펼쳐서 확인한다. 기존 원천 계정과 근거 열람 기능을 유지한다.
- `/examples/financial-cashflow`는 같은 컴포넌트에 명시적 가상 건설 기업 데이터를 사용한다. 실제 결과의 누락값을 예시 금액으로 대체하지 않는다.

## 검증

### 이익 → 현금 브리지 추가

두 카드 아래 전체 너비로 영업이익에서 영업활동현금흐름까지의 워터폴을 표시한다. 기존 API의 감가상각비와 매출채권·계약자산·재고자산·매입채무·계약부채 비교 잔액을 사용한다. 자산은 전기 잔액에서 당기 잔액을 빼고, 부채는 당기에서 전기를 뺀 방향으로 표시한다. 이는 현금흐름표 조정 내역이 아닌 **잔액 증감에 따른 근사**다. 환율·비현금 거래·사업결합 효과를 분리하지 못하므로 실제 현금 유출의 확정 원인으로 설명하지 않는다.

당기 영업CF에서 영업이익과 표시한 조정을 뺀 차액은 **기타·미분해 조정**이다. 확인되지 않은 차액에 이자·법인세 명칭을 붙이지 않는다. 누락된 비교 잔액은 0으로 채우지 않고 차트에서 생략하며 설명 표에 미확보로 표시한다. 이때 운전자본 전체 영향도 보류한다. 시작·종료 금액이 없으면 차트 전체를 보류한다. 조정 계산은 원 단위 소수 여섯 자리 정수로 수행하며, 마지막 음수 현금흐름은 빨간색으로 표시한다. 좁은 화면에서는 차트 영역 안에서 가로로 스크롤한다.

`차이 설명 표 펼치기` 버튼과 펼침 영역에서 금액·산출 근거·미확보 항목을 확인한다. 예시에서는 1,284억원에서 -310억원으로 이어지고, 잔여 조정은 -534억원이다. 별도 백엔드·DB 변경은 없다.

추가 검증: 현금흐름 관련 단위 검사 7개, 실제 결과·예시 브라우저 검사 4개, TypeScript·ESLint·프로덕션 빌드 통과. 브라우저에서 표 열기·접기와 390px 가로 넘침을 확인했다.

### 운전자본·현금흐름 확인 항목 추가

브리지 아래 두 카드를 나란히 배치한다. 건설은 계약자산·계약부채 증감을, 나머지 업종은 매출채권·재고자산 증감을 표시한다. 회수기간·재고 회전일수·매입채무 지급일수·현금전환주기는 기존 서버 지표를 사용하고 미정인 잔액·기간 정책을 새로 확정하지 않는다. 실제 지표가 보류이면 보류 사유를 표시한다. 값이 제공되면 전기·당기 위치와 차이를 비교한다. 자산 회수·재고·현금전환주기 증가 및 매입채무 지급기간 단축은 현금회전 방향상 빨강이다. 지급기간 연장을 신용위험 해소로 단정하지 않는다. 일수의 근사 상태와 산출 기준은 펼침 표에서 확인한다.

현금흐름 확인 표는 음수 영업CF를 비율 대신 금액과 계산 불가 상태로 보여 준다. 단기차입의 상환 용도·배당 지급 자료가 없어 해당 여부는 판단 보류다. 흑자 중 영업CF 음수는 두 값이 모두 확인된 비교기간만 세며 연속 연수로 단정하지 않는다. 다른 체크·검토 화면으로 저장·전송하는 기능은 추가하지 않았다.

가상 예시의 142/118일·38/33일·61/66일·119/85일은 배치 확인용 값이며 실제 정책·산식이나 누락값에 적용하지 않는다. 백엔드 변경은 없다. 실제 보류·음수 영업CF·누락 기간 처리 단위 검사 및 실제 결과·예시 브라우저 검사로 확인한다.

추가 후 검증: 프런트엔드 전체 테스트 107개와 실제 결과·예시 브라우저 검사 4개 통과. TypeScript·ESLint·프로덕션 빌드를 확인했다. 390px 화면에서 표·차트 내부 스크롤을 사용하며 페이지 전체의 가로 넘침은 없다.

### 업종 비교·현금흐름 구성 추가

업종 비교는 영업이익률·부채비율·영업CF/영업이익을 전환해 자사 위치와 비교 기업 분포·중앙값을 표시한다. 비교 입력의 업종·기간·회계 범위가 현재 결과와 일치해야 하며 가상 분포는 예시 경로에서만 허용한다. 실제 API에는 비교 표본이 없어 자사 값만 표시하고 중앙값은 보류한다. 외부 평균·출처·표본수를 임의로 만들지 않는다. 예시에서는 가상 기업 14곳의 분포와 산출 중앙값을 표시한다.

현금흐름 구성은 같은 CF의 기초현금 + 영업·투자·재무활동 + 잔액 차이 조정 = 기말현금이다. 원 단위 소수 여섯 자리까지 정수로 계산하며 차액이 있으면 별도 조정으로 표시한다. 조정 차액을 환율 영향으로 확정하지 않는다. 기초·기말 또는 활동 금액이 누락되면 차트를 보류하고 펼침 표로 확보 금액을 제공한다. 재무활동 유입 전체를 차입 유입으로 단정하지 않는다.

백엔드 계정 매핑 `financial-accounts-v3`에 CF의 기초·기말 현금 계정을 추가했다. CF 표준 ID 또는 정확한 비표준 계정명만 사용하고 BS 현금이나 전기 잔액을 대체하지 않는다. 기존 저장 결과는 변경하지 않는다. 해당 계정이 없는 이전 결과는 재수집·분석이 필요하다. 로컬 API·Worker 이미지를 빌드·적용했고 두 컨테이너의 Healthy 상태를 확인했다.

검증: 프런트엔드 전체 109개, 관련 브라우저 4개, 백엔드 현금 계정 매핑 단위 검사 3개 통과. TypeScript·ESLint·프로덕션 빌드 통과. 전체 백엔드 pytest는 실행하지 않았다. 비교 범위 불일치·실제 화면의 가상 분포 차단·현금 차이 조정·누락 보류·탭 전환·모바일 가로 넘침을 확인했다.

### 기존 두 카드 검증

- 단위 검사: 영업이익 분해의 0 교차, 소수 금액 정합성, 실제 0, 누락·불일치 보류, 현금흐름 설명의 전환 조건.
- 브라우저 검사: 실제 API 응답 기반 재무 결과에서 두 차트 표시, 예시 메뉴 이동·금액 표·음수 현금흐름, 데스크톱·태블릿·390px 화면의 가로 넘침과 실행 오류 확인.
- 검증 결과: TypeScript·ESLint·프로덕션 빌드 통과, 프런트엔드 전체 102개 테스트 통과, 관련 브라우저 검사 8개 통과. 새 컴포넌트·차트·검사 파일의 Prettier 검사와 `git diff --check`도 통과했다. 빌드는 기존 대형 번들 경고를 출력한다.

기존 핵심 요약의 적용 내역은 [시각화 요약 검증](20_visual-financial-summary-validation.md), API 계약과 기존 제한은 [재무 API](../../backend/README.md#financial-api)를 따른다.
