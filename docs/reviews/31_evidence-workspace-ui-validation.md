# 주석 추출 현황·선택 근거 화면 검증

검증일: 2026-11-01 (Asia/Seoul). 통합 근거/사실 검수의 업무 계약은
[선택 근거 안내](../../backend/data/evidence/README.md)를 유지한다.

## 변경

사용자가 제공한 참고 화면의 1·2번 영역에 따라 첫 화면을 추출 현황 표와 선택 근거 카드로
변경했다. 공통 6항목의 구분·검출 상태·건수·원문 위치를 표시하고, 행을 선택하면 오른쪽에
금액·만기·상대방·기준 기간·접수번호·인용문을 표시한다. 원문은 기존 Modal과 문맥 컴포넌트로
열며 실제 저장된 셀·본문을 조회한다. 업종별 항목과 금액 예시는 운영 데이터에 추가하지 않았다.

원문 키워드 일치는 `검색 후보`, 저장된 구조화 사실은 `검출`, 명시적 부정 사실은 `공시상 없음`으로
구분한다. 검출은 검수 승인과 구분하며, 확보하지 않은 금액·만기·상대방·사실 기준 기간은 임의로
채우지 않는다. 사실 목록은 끝까지 페이지 조회하고 반려·대체 이력은 현황에서 제외한다.
미확보 원문·단순 미검출을 명시적 공시 부정으로 판단하지 않는다.

상단에는 위험징후 패널·주석 추출 근거·AI 요약 메뉴를 두고 추출 근거를 기본으로 연다.
위험징후는 기존 규칙 입력 패널을 연결하며 AI 요약은 준비 상태로 표시한다. 기존 검색·목차·
사실 검수·수정 기능은 아래 `상세 검색·사실 검수`에 접어 두었다. 넓은 화면은 두 열,
태블릿/모바일에서는 순서대로 쌓으며 표만 내부 가로 스크롤을 허용한다. 기존 화면의 색상·폰트·
패널·버튼을 사용하며 서버 API·검수 승인 조건·모델 보류 정책은 변경하지 않았다.

## 검증

- 관련 React 검사 3파일·11 passed: 추출 표·원문 셀 안전 표시·금액/만기/미확보 표시,
  원문 후보 선택 시 검출/금액 오표시 방지·사용자 전환·예측 보류·검수 승인 조건을 확인했다.
- Playwright Chrome PC(1440×1000)·태블릿(820×1180) 2 passed. 각 실행에서 모바일
  390×844로도 전환해 검색 결과·표·검수 패널·수정 폼의 가로 넘침이 없는지 확인했다.
  활성 메뉴·6행 현황·행 선택/카드 전환·원문 패널, 기존 검색·검수·수정 흐름을 검사했다.
  이 자동 검사는 합성 API 응답으로 재현하며 실제 사실 정확도를 검증하는 검사가 아니다.
- 별도 실제 서비스 확인으로 현대건설/20260318001395/OFS를 새 검증 세션에서 열어
  자동 기본 검색·담보 행 선택·원문 패널 표시를 실행했다. Chrome 1640px·820px에서 가로
  넘침=false, pageerror=0이었다. 세션은 종료했고 사실 승인·실제 모델 호출은 하지 않았다.
- PC/모바일 캡처를 열어 레이아웃과 폼을 시각 확인했다. 자동 검사 캡처는 Git 제외
  `frontend/test-results/`, 실제 보고서 캡처는 `frontend/.run/evidence-ui-preview/`에 저장했다.
  실제 보고서 화면 캡처의 사용자 코드 영역은 가려서 보관한다.
- TypeScript·Vite 빌드와 ESLint 통과. Vite의 기존 큰 청크 경고는 유지된다. 백엔드 변경이
  없어 DB migration·백엔드 전체 검사를 다시 실행하지 않았다.

앞선 문서 정합성 점검 변경과 원본 dump는 이 UI 변경 범위에서 제외한다. 외부 배포는
수행하지 않았다.
