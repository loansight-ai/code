기업 원장 갱신과 분류 코드 계약은 [백엔드 안내](../../backend/README.md#기업-검색), 입력 자료 기준은 [제공 자료 README](../../opendart_ksic11_sync/README.md)에서 관리한다. 원본 기업 CSV는 수정하지 않았고 로컬 입력으로 유지했다.

기업 CSV SHA-256은 `6ef256abea6fa4e77d826d7ee8a5beea2324ee4e6930d4c50da53fdd49ac618e`이다. 기준선 수입에서 기업개황 조회일·응답 해시를 허위로 생성하지 않았다. `--profile-limit 0`으로 실제 수입을 수행해 대량 기업개황 API 호출 없이 동기화 상태와 검토 목록을 저장했다. 원본·스냅샷·증분은 Git에서 제외한 로컬 아티팩트에 보존했다.

## 실행 검증

| 방법 | 기대 결과 | 실제 결과 |
|---|---|---|
| 백엔드 단위 검증 전체 | 주간 경계·재시작·차이 비교·실패 시 보존·CSV/코드표 검증·원본 코드 분리·충돌 분리·동시 실행 잠금·API 생명주기·요청 제한 재시도 | 48개 통과 |
| 프론트 Vitest 전체 | 기존 흐름과 검색 동작 유지 | 46개 통과 |
| KSIC11 표시 전용 Vitest | 코드/명칭·DART 미확보 상태·실제 기업 선택 | 2개 통과 |
| Chrome desktop/tablet 실제 검색 | 삼성전자 KSIC11 코드·명칭·원본 업종코드 구분, 영문 종목코드, 결과 없음 | 2개 E2E 통과 |
| 프로덕션 빌드·타입·ESLint·Ruff | 번들·정적 검사 성공 | 통과. 기존 500kB 번들 크기 경고는 남음 |

주간 기한은 모의 시각으로 7일 직전/정각을 검증했다. 실제 7일 경과를 기다린 검사는 수행하지 않았다. 실제 기업개황 대량 호출·신규 기업 업종명 원천 연결·서비스 대상 업종 판정·기존 Compose 서비스 재배포는 수행하지 않았다. 브라우저 검증은 별도 Native API 8018/Vite 5188 포트에서 자동 기업개황 조회를 끄고 실행했다. 스크린샷은 Playwright `test-results/`에 생성하고 desktop 표시를 확인했다.

코드표의 정확한 명칭 매칭과 반복 명칭의 공통 상위 분류 선택은 단위 검증했다. DART `company.json`에는 업종명 필드가 없으므로 코드표만으로 신규 기업의 업종을 추정하지 않는다. 신규/변경 기업의 KSIC 자동 매핑에는 검증된 별도 업종명 원천 또는 명칭 매핑이 추가로 필요하다.
