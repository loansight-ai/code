독립 원문 수집 버튼을 재무 분석 체크박스로 통합하고 기본 분석→구조화 완료→Codex 탐색→후보 검증·재계산→구조화 원문 셀 강조를 연결했다. 데이터 계약·DB 보존·재시도 조건은 [백엔드 담당 문서](../../backend/README.md#financial-note-enrichment), 화면 동작은 [프론트 안내](../../frontend/README.md#financial-summary)에서 관리한다.

## 검증 결과

| 검증 | 결과 |
|---|---|
| 백엔드 비통합 테스트 | 101개 통과, 별도 환경변수가 필요한 기존 Codex handshake 1개 skip |
| 재무 DB 흐름·마이그레이션 | 10개 통과. 기본 4개·선택적 보완 3개·수집/구조화 실패 2개·upgrade/model check/downgrade 1개 |

| 정적 검사·빌드 | Ruff·TypeScript·ESLint·Vite 통과. 기존 큰 청크 경고 유지 |
| 실제 API·큐·DB·Codex | 오뚜기 OFS에서 BASE_ANALYSIS→WAITING_STRUCTURE→ENRICHING→COMPLETED 확인 |
| 실제 Chrome | 기본 해제 체크박스·독립 버튼 제거·반영 8건·원문 셀 강조 및 화면 내 위치·산식 근거·태블릿 가로 넘침 없음·페이지 오류 0 |

DB 통합은 `_test` 데이터베이스의 독립 스키마를 사용했다. 구조화 전 보완 작업 미생성, 두 Relay 동시 실행 시 한 번만 예약, 중복 Worker 전달 무반영, 인용 불일치·Codex 시간 초과·원문/구조화 실패 시 기본 결과 보존을 확인했다. 직접 셀 검증은 금액·단위·기간·범위 오류, 잘라낸 기간/통화 인용의 모호성, 충돌 후보, 특수관계자·종속기업 부분 금액을 거부하는 단위 테스트를 포함한다. 원문 셀 뷰어는 병합 좌표와 과도한 rowspan 거부도 검증했다. 최초 프론트 기본 병렬 실행에서 기존 주석 화면 로딩 테스트가 시간 초과되어 동시 Worker 2개로 전체를 다시 확인했다.
