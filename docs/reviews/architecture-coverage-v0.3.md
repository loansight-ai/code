## 검토 대상과 결론

- [기능 명세서 v0.0.4](https://github.com/loansight-ai/docs/blob/main/01-planning/functions.md): N-F01~41 전체. 조회한 GitHub 파일 blob SHA는 `5dad72a65c14672a3ff61ed31cb4931cb9e07d87`이다.
- [화면설계서 PDF](<../LoanSight AI_화면설계서_v0.0.2_261026.pdf>): 물리 페이지 1~11의 화면·설명·팝업·예외를 확인했다. 파일 SHA256은 `8ad2880327e7697212a16241009c2e90a27e966e093db8496098fabd7225e640`이다.
- [현재 아키텍처 v0.3](../LoanSight_AI_Architecture_v0.3.md): 로컬 커밋 `d1df9f3`의 내용 기준이며 현재 파일은 `docs/`로 이동했다.

**기술 구조는 유효하다.** React SPA, FastAPI, Worker, PostgreSQL, RabbitMQ, SSE와 현재 모듈 분리로 두 문서의 기능을 수용할 수 있다. 추가 마이크로서비스나 통신 방식 교체가 필요한 요구는 발견하지 못했다.

**현재 문서만으로 필수 기능 전체의 구현 계약이 완성됐다고 판단할 수는 없다.** 필수 기능을 선택·후순위처럼 표현한 부분, 이미 정의된 내용을 미정으로 남긴 부분, 화면 동작에 필요한 저장·API 계약이 빠진 부분이 있다. 아래 보완은 기존 모듈과 스키마·API·개발 단계에 반영할 수 있다.

파일명은 화면설계서 v0.0.2이지만 PDF 표지에는 v0.0.1·작성 2026.10.24로 표기되어 있다. 본 검토는 파일명만으로 버전을 추정하지 않고 위 해시의 실제 파일을 기준으로 한다. 원본의 검토·승인 상태나 예시 수치는 변경하지 않는다.

## 기능 41개별 매핑

아래는 [기능 명세서](https://github.com/loansight-ai/docs/blob/main/01-planning/functions.md)의 각 ID를 현재 아키텍처에 배치한 검토 결과다.

- **반영:** 책임 모듈과 주요 원칙이 설계에 있다. 구현·테스트 완료를 의미하지 않는다.
- **보완:** 담당 모듈은 있지만 해당 기능의 데이터·API·상태 계약을 보완해야 한다.
- **불일치/누락:** 필수 범위와 표현이 다르거나 해당 업무의 설계가 빠져 있다. 현재 기술로 구현할 수 없다는 뜻은 아니다.
- **보완 기능/확장:** 명세의 범위 구분을 유지하며 필수 기능 완료에 포함하지 않는다.

## 이미 정해진 내용과 유지할 미정 사항

기능 명세 N-F36과 N-F39 및 PDF 6~7쪽에는 다음 명칭이 있다. 명칭 자체를 새로 결정할 필요는 없다.

| 구분 | 명칭 |
|---|---|
| 판단 축 6개 | 상환재원, 유동성/만기, 재무구조, 우발/부외 부담, 외부 평가, 담보/회수 여력 |
| 공통 추출 6항목 | 감사의견/계속기업, 차입 만기/재무약정, 신용등급, 담보, 소송/제재, 부외/후속사건 |

반면 위험 수치·기간 임계값, 업종 비교 최소 표본, 세부분류·복합 비중, 금리/금융원가 근사 허용, 임대보증금 차입 포함, 정확한 라벨 판정·심각도·성능 수용 기준, 승인 주체는 원문에서도 미정이다. 검토 과정에서 수치를 임의로 채우면 안 된다.

복합 위험 사건이라는 대표 예측 목표와 아직 미정인 복합 라벨의 구성·판정 세부 규칙은 구분한다. 또한 공시상 조건의 존재와 실제 사건 발생, 매출채권의 연체와 회사 차입의 연체를 구분해야 한다.

## 적용 순서 제안

1. G01~G04의 필수 범위·목표·일정 표현부터 정합화한다.
2. 수동 입력/업종 override, 비교군, 원문 구간, 사건/관찰 라벨, 모델 평가, 원문 열람·체크, 초안 revision, 검수·실험 기록의 논리 모델과 API 계약을 정의한다. 모든 개념에 별도 테이블을 강제하지 않는다.
3. 각 기능 ID→담당 모듈→API/산출물→화면→검수 기준을 연결한다. 사용자 식별·수치형 임계값 등 미정 항목은 구현 전 결정 시점을 유지한다.
4. 기존 수직 MVP와 MQ·SSE 장애 복구 기준에 PDF의 입력 부족·원문 열람 게이트·재생성 충돌·3/5개년 자료 부족 시나리오를 추가한다.

이번 검토에서는 기능 명세서, 화면설계서, 기존 README·아키텍처 원본을 수정하지 않았다. 실행·데이터 수집·모델 품질 및 UI 구현 여부는 검증하지 않았다.
