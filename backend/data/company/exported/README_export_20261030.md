# 분석 DB 내보내기 파일 설명 (2026-10-30)

로컬 분석 DB(PostgreSQL 16, DB `loansight`)에서 서비스 연동용으로 내보낸 CSV 3개를 설명합니다.

- 내보낸 날: **2026-10-30**
- 원천 수집 기준일: **2026-10-26** (OpenDART 조회 범위 `20150101~20261026`)
- 대상: 제조·도소매·건설·부동산임대 4개 업종의 **2,271개사**
- 아래 건수·비율은 모두 이 파일에서 직접 센 값입니다.

| 파일 | 원본 표 | 행 | 열 | 한 행의 의미 | 키 |
|---|---|---|---|---|---|
| `fs4_wide_ok_20261030.csv` | `mv_fs4_wide_ok` (구체화 뷰) | 18,417 | 130 | 회사 × 사업연도의 표준화 재무제표 | `corp_code` + `bsns_year` |
| `risk_event_20261030.csv` | `risk_event` | 2,698 | 17 | 공시로 찾은 상환·연체 위험 사건 후보 1건 | `id` |
| `event_coverage_20261030.csv` | `event_coverage` | 2,271 | 22 | 회사별 위험 사건 조회 범위·결과 | `corp_code` |

## 파일 형식

| 폴더 | 인코딩 | 셀 안 줄바꿈 | 용도 |
|---|---|---|---|
| `export/` (원본) | UTF-8, BOM 없음 | `risk_event.detail`에 그대로 있음 (셀 786개) | 서비스 적재·분석용. `pandas.read_csv(encoding="utf-8")`로 읽음 |
| `export/excel/` (사본) | UTF-8 BOM | 공백으로 바꿈 | 엑셀 더블클릭 확인용. **저장소에 넣지 않음** |

- 코드 열(`corp_code`, `rcept_no` 등)은 앞자리 0이 있으므로 **문자열로 읽습니다.** (`dtype={"corp_code": str, "rcept_no": str}`)
- 빈칸은 DB의 `NULL`입니다. **0과 다릅니다.** 빈칸을 0으로 채우지 않습니다.
- 불리언은 PostgreSQL 표기 `t`/`f`입니다.

## 세 파일의 관계

```
event_coverage (2,271개사: 위험 사건을 어디까지 조회했는지)
   ├── risk_event (538개사, 2,698건: 찾은 사건 후보)      ← corp_code로 연결
   └── fs4_wide_ok (2,091개사, 18,417 회사·연도: 재무값)   ← corp_code로 연결
```

- `risk_event`의 회사는 모두 `event_coverage`에 있습니다.
- `event_coverage` 중 **180개사는 `fs4_wide_ok`에 재무값이 없습니다.** OpenDART 전체 재무제표 API에 자료가 없는 회사(대부분 기타법인·코넥스)입니다.
- 그래서 `risk_event`의 92개사는 재무값과 이어지지 않습니다.

## 1. `fs4_wide_ok_20261030.csv` — 표준화 재무제표

### 꼭 알아야 할 점: 연결/별도가 섞여 있음

| 업종 | 연결(CFS) | 별도(OFS) |
|---|---|---|
| 제조업 | 12,391 | 3,264 |
| 도소매업 | 1,555 | 322 |
| 건설업 | 536 | 141 |
| 부동산임대업 | 117 | 91 |
| **계** | **14,599 (79%)** | **3,818 (21%)** |

- 수집할 때 **연결을 먼저 받고, 연결이 없을 때만 별도를 받았습니다.** 그래서 한 회사·연도에 한 행만 있고, `fs_div`로 어느 쪽인지 표시합니다.
- **493개사는 연도별 추세 안에 연결과 별도가 섞여 있습니다.** (예: 에스마크 2015 OFS → 2016 CFS) 추세를 그리거나 전기 대비 증감을 낼 때 `fs_div`가 바뀌는 연도를 표시해야 합니다.
- 업종 분포를 만들 때는 `fs_div`별로 나눠서 계산합니다.
- 서비스 API 기본값은 `scope="OFS"`이고, 저장소 README(10/29)는 "연결 우선, 없으면 별도"입니다. 연결 회사의 별도 재무제표는 아직 수집하지 않았습니다.

### 알려진 데이터 이슈

- `rcept_no` 중복 1건: 코스나인 2024·2025가 같은 접수번호(`20260324000091`)입니다. 정정 과정의 수집 이슈로 보이며 확인이 필요합니다.
- `bs_ta`(자산총계)와 `bs_tle`(부채와자본총계)가 1원 넘게 다른 행이 15개 있습니다.

## 서비스 연동 시 권장 사항

1. **저장소(`backend/data/`)에는 `export/` 원본을 BOM 붙은 UTF-8로 바꿔서 넣습니다.** 기존 `backend/data/company/companies_opendart_ksic11.csv`와 형식을 맞춥니다. `detail`의 줄바꿈은 지우지 않습니다.
2. 파일 하나가 100MB를 넘지 않습니다(최대 `fs4_wide_ok` 약 20MB). GitHub에 그대로 올릴 수 있습니다.
3. 업종 분포는 `fs4_wide_ok`에서 **업종 × 사업연도 × `fs_div`**별로 계산합니다. 서비스가 계산하는 자사 값과 산식(특히 총차입금의 리스 포함 여부, EBITDA, 이자비용 출처)이 같은지 몇 개 회사로 대조한 뒤 넘깁니다.
4. `risk_event`는 `verified`가 비어 있으므로 화면에는 "원문 확인 전 후보"로 표시합니다.
5. 사건이 없다는 표시는 `event_coverage`에서 조회가 완료된 회사·기간에만 씁니다.
